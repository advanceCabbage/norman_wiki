## 零、写在前面

Harness 工程的本质，是对大模型能力边界的补充。正因如此，Harness 本身并不是一套固定不变的能力集合，而会随着模型能力的演进不断迁移。

过去被证明有效的 Harness 设计，在模型能力增强后，未必仍然适用，甚至可能成为新的约束。例如，Claude Code 最近提到，他们正在减少 Few-shot 的使用：在对 Fable 5 的能力测试中发现，Few-shot 可能会将模型限制在预设的探索路径中，从而抑制其自主推理与探索能力。

因此，真正重要的并不是沉淀一套“最佳”的 Harness 方法论，而是具备识别模型能力短板、判断何时应引入或移除 Harness 的能力。

> 没有放之四海而皆准的 Harness，只有最适合特定模型、特定任务与特定阶段的 Harness。

## 一、提示词工程的八大技巧

### 1.1 清晰指令

这是所有技巧中**性价比最高**的一条：写清楚你想要什么。具体可以从五个方面入手。

- <span style="display:inline;color:#35b378;font-weight:bold;">明确受众与语气</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：说明面向谁，AI 会自动调整用词深度和表达风格。</span>
    - 同一个问题，不同受众：
    - ❌ 解释一下什么是量子纠缠。
    - ✅ 用类比的方式，向一个从未接触过物理学的高中生解释量子纠缠。
- <span style="display:inline;color:#35b378;font-weight:bold;">规定输出篇幅</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：没有约束 vs. 有约束。</span>
    - ❌ 介绍一下北京。
    - ✅ 用不超过 200 字介绍北京，重点突出历史文化和旅游亮点。
- <span style="display:inline;color:#35b378;font-weight:bold;">同时给出要和不要</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：用正面约束 + 负面约束双重限定，边界更清晰。</span>
    - ✅ 请分析这款产品的市场竞争力，只讨论技术优势和定价策略，不要涉及公司历史和团队背景。
- <span style="display:inline;color:#35b378;font-weight:bold;">说明最终用途</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：“这段文字用于……”能帮助 AI 选择恰当的风格。</span>
    - ✅ 请将以下技术文档改写成适合发布在公众号的科普文章，读者是对技术感兴趣但没有专业背景的普通大众。
- **把复杂任务拆成步骤**：
    - 请按以下步骤处理这段用户评论：1. 判断情感倾向（正面/负面/中性）；2. 提取用户最关心的 1—2 个问题。

### 1.2 角色设定

AI 在训练过程中学习了大量不同领域专家的表达方式和知识体系。当你给它设定一个角色时，相当于**激活**了它在那个领域积累的知识模式。

**有效角色的三要素：**

1. <span style="display:inline;color:#35b378;font-weight:bold;">专业领域</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：是什么专家，经验如何。</span>
2. <span style="display:inline;color:#35b378;font-weight:bold;">行为方式</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：怎么沟通，什么风格。</span>
3. <span style="display:inline;color:#35b378;font-weight:bold;">核心立场</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：有什么原则或偏好。</span>

示例：你是一位专注于商业写作的文案顾问，擅长将复杂信息转化为简洁有力的表达，风格偏向《经济学人》的精炼感。

### 1.3 XML 标签

当你的提示词里既有**告诉 AI 做什么的指令**，又有**需要 AI 处理的数据**时，把它们清晰地分开非常重要。XML 标签是 AI 天然具备敏感识别能力的结构化方式。

常见的 XML 标签：

- <span style="display:inline;color:#35b378;font-weight:bold;">document</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：待分析的文档或文章。</span>
- <span style="display:inline;color:#35b378;font-weight:bold;">user_input</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：来自外部的、不完全可信的用户输入。</span>
- <span style="display:inline;color:#35b378;font-weight:bold;">context</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：背景信息、参考资料。</span>
- <span style="display:inline;color:#35b378;font-weight:bold;">example</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：示例内容。</span>
- <span style="display:inline;color:#35b378;font-weight:bold;">question</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：需要回答的具体问题。</span>
- <span style="display:inline;color:#35b378;font-weight:bold;">data</span><span style="display:inline;color:#3f3f3f;font-weight:normal;">：需要处理的数据。</span>

> **最佳实践：** 标签名称要有实际含义。`<resume_A>` 比 `<text1>` 更好——AI 能从标签名理解内容的性质，输出质量会更高。

示例：

```text
请完成以下任务：
1. 比较两份简历各自的优势
2. 判断谁更适合“产品经理”职位
3. 给出 50 字以内的录用建议

<resume_A>
张三，5 年产品经验，主导过三款 DAU 百万级产品，
擅长数据分析和用户访谈……
</resume_A>

<resume_B>
李四，3 年产品经验，有 0-1 创业经历，
连续两次带领团队完成融资里程碑……
</resume_B>

<position>
产品经理，负责 B2B SaaS 产品线，
有 PMF 探索经验者优先。
</position>
```

### 1.4 思维链

对于复杂问题，直接要求 AI 给答案，效果往往不如让它**先思考，再作答**。简单说：**让 AI 把草稿写出来，它就不容易犯错。**

#### 1.4.1 三种触发思维链的方式

**方式 1：用标签隔离思考过程**

```text
请在 <thinking> 中写下你的推理过程，
在 <answer> 中给出最终答案。

<thinking> 中的内容不需要完美，像草稿一样思考即可。
```

**方式 2：直接要求一步一步来**

```text
这道题请一步一步地思考，展示每一步的推导过程。
```

**方式 3：先列论据再下结论**

```text
请先分别列出支持和反对的理由，再给出你的综合判断。
```

### 1.5 少样本示例

**直接给例子**比反复描述更有效。这种方法叫做**少样本学习（Few-Shot Learning）**。

#### 1.5.1 好示例的三个标准

**1. 覆盖典型变体**：如果是分类任务，每个类别都要有示例。

```text
正面示例：「这个产品真的很好用！」→ positive
负面示例：「完全是浪费钱，后悔购买。」→ negative
中性示例：「收到了，外观和图片一致。」→ neutral
```

**2. 格式完全统一**：示例的输入格式和输出格式必须保持一致。

**3. 质量高于数量**：2—3 个精心设计的示例即可。

### 1.6 防幻觉设计

幻觉（Hallucination）是指 AI 自信地输出错误的、不存在的，或者凭空捏造的信息。这是大语言模型的固有局限，但通过提示词设计，可以大幅降低它的发生率。

#### 1.6.1 四种防幻觉策略

**策略 1：明确允许 AI 说“我不知道”（最简单有效）**

```text
如果你不确定某个信息，请直接说“我没有关于这个问题的可靠信息”，
不要猜测或编造答案。不确定 ≠ 失败，诚实才是好助手。
```

**策略 2：限制 AI 只使用你提供的信息**

```text
请只根据 <reference> 标签中的内容回答问题。
如果参考资料中没有足够的信息，请回答：“根据提供的资料，无法回答这个问题”。
```

**策略 3：先找证据，再给结论**

```text
在回答之前，请先在 <evidence> 中找出文档里
直接支持你结论的句子或段落，再在 <answer> 中给出结论。
如果找不到支持性证据，就说找不到。
```

**策略 4：降低随机性（API 开发者）**

在 API 调用中将 `temperature` 设为 `0`，让模型的输出更保守、更确定，减少“创意性”发挥带来的错误，适合事实性任务。

### 1.7 提示词链

当一个任务过于复杂，单条提示词无法可靠完成时，可以把它**拆分成多个子任务，依次执行，前一步的输出作为下一步的输入**——这就是提示词链（Prompt Chaining）。

**适合场景：** 长文档分析、代码生成、内容创作、数据处理。

```text
# 第一步：信息提取
请从以下简历中提取关键信息，以 JSON 格式输出：
- name（姓名）
- years_exp（工作年限，数字）
- skills（技能列表）
- last_title（最近职位）

<resume>{简历原文}</resume>

# 第二步：岗位匹配（将第一步的 JSON 作为输入）
根据以下候选人信息和岗位要求，打出 0-10 的匹配分，
并说明主要匹配点和不足点。

<candidate>{第一步的 JSON 输出}</candidate>
<job_requirements>{岗位要求}</job_requirements>

# 第三步：生成面试邀请（将第二步结果作为输入）
如果匹配分 >= 7，起草一封简洁的面试邀请邮件；
如果匹配分 < 7，起草一封婉拒邮件。

<evaluation>{第二步的评估结果}</evaluation>
```

### 1.8 元提示

当你不知道如何写一个好的提示词时，有一个被严重低估的方法：**直接让 AI 帮你写或改进提示词。**这就是元提示（Meta-Prompting）——用提示词来生成提示词。

#### 1.8.1 三种元提示用法

- **从零生成提示词**。
- **诊断并改进现有提示词**。
- **针对具体输出反向推导提示词**。

## 二、团队智能助手的提示词示例

```text
你是负责 XXX 团队的智能客服助手，擅长友好地与用户交流，擅长依据知识库检索结果准确回复用户的咨询问题。但如果你不确定某个信息，请直接说“我没有关于这个问题的可靠信息”，不要猜测或编造答案。不确定 ≠ 失败，诚实才是好助手。对于用户的问题，回复限制在 300 个字符内，精确列出解决思路和参考文档。

<context>
XXX 团队负责公司内各端 API 原子能力，包括 iOS、Android、Harmony、微信小程序、H5 等 API 能力。各端 API 能力大致相同，但同时也存在差异性。你将收到用户对 API 相关问题的咨询，你需要严格按照知识库检索内容回复用户问题。
</context>

<example>
- 用户提供的问题不清晰、不完整时，礼貌地请用户补充完善问题信息
用户问题：使用 chooseImage 报错
assistant：你好，请问是哪端 API 报错，是 iOS、Android 还是其他呢？另外报错信息是什么呢？

- 好的问题回答示例
用户问题：Android 端使用 uploadFile 报错，报错信息为：无上传权限
assistant：你好，依据 XXX 工单记录，使用 uploadFile 无权限问题为，你无 S3 桶上传权限，请查看 XXX 文档添加 S3 权限；你也可以看历史工单 XXX 的处理记录。
</example>
```
