## 一、传统 NLP：流水线式的任务拆解

**NLP（Natural Language Processing，自然语言处理）**。

### 1.1 工作方式

传统 NLP 的工作方式是「流水线」式的：一个完整任务需要被拆分成多个独立步骤，每一步都由一个专门的模型完成。

原因在于，当时小模型的能力有限；每个子问题都必须单独训练模型才能解决。

以智能客服为例，第一步通常是分词。分词模型依赖大量人工标注语料；一旦遇到训练中没见过的新词，模型就可能无法工作。这就是著名的 OOV（Out-of-Vocabulary，未登记词）问题。

### 1.2 存在的问题

- 每一步都需要自己的模型、训练数据和标注规范；整个过程冗长且脆弱，前一步失败，后续步骤也会受到影响。
- 迁移成本高：换一个领域，例如从客服切换到医疗问答，几乎所有模型都需要重新训练。

## 二、BERT：预训练 + 微调的两阶段范式

**BERT（Bidirectional Encoder Representations from Transformers，基于 Transformer 的双向编码器表示）**。

2018 年，谷歌推出 BERT，整个领域迎来了一次大转折。BERT 的核心创新是「预训练 + 微调」两阶段范式。

### 2.1 预训练阶段

通过预训练，BERT 学会了“看懂文字”的能力，主要依靠两件事：

- **MLM（Masked Language Model，掩码语言模型）**：随机遮掉句子中 15% 的词，让模型根据上下文猜被遮住的词是什么。
- **NSP（Next Sentence Prediction，下一句预测）**：给模型两个句子，让它判断两者是否连续。

这两种方式都不需要人工标注，依靠原始文本就能训练，因此可以使用海量数据。

### 2.2 微调阶段

通过微调，BERT 可以将每个 Token 的向量表示用于具体任务。例如，做问答时，需要接入一个抽取式 QA 头。

### 2.3 存在的问题

- BERT 不擅长生成文本。它的预训练目标是 MLM，类似“填空题”，每次只猜测一个被遮住的词。
- BERT 的输出是“向量表示”，而不是“文本”。每种任务仍需要单独设计标注数据并进行微调。

## 三、LLM：把所有 NLP 任务统一为预测下一个 Token

**LLM（Large Language Model，大语言模型）**。

LLM 最根本的转变，是把所有 NLP 任务统一成一件事：**预测下一个 Token**。

模型能够预测下一个 Token，依靠的是「自回归 + 因果掩码」：

- **CLM（Causal Language Modeling，因果语言模型）**：给定一段文本，模型从左到右逐字往后猜；每一步都要预测下一个 Token。
- **自回归（Autoregressive）**：下一步的预测依赖上一步的输出。

### 3.1 数据规模与模型参数

两个关键点决定了模型能力：**数据规模 + 模型参数**。

- **数据规模**：BERT 时代的训练数据是几十亿词，而 GPT-3 使用了 3,000 亿 Token。因果语言模型不需要人工标注，互联网上的文本天然就是合格的训练数据。
- **参数规模**：BERT 的参数量约为 0.3B，GPT-3 为 175B，Kimi K3 为 2,800B。

数据规模与参数规模的堆叠，使得 LLM 走向新的能力边界。

### 3.2 上下文学习与涌现能力

LLM 走强的另外两个重要原因，是 **In-Context Learning（上下文学习）** 和 **Emergent Abilities（涌现能力）**。

- **上下文学习**：在 Prompt 中给模型几个例子，模型便能学会新的任务，不需要更新参数。下面的例子中，模型能自动给出“橘子 → orange”。

```text
苹果 → apple
香蕉 → banana
草莓 → strawberry
橘子 →
```

- **涌现能力**：小模型上几乎看不到的能力，会在数据规模和参数规模到达某个临界点后突然表现出来，例如多步算术、上下文学习和跨语言迁移。

### 3.3 为什么会涌现？

业界给出的工程经验叫作 **Scaling Law（缩放定律）**：模型规模、训练数据量、训练算力三者之间存在可预测的关系。当这三者按一定比例同时放大时，模型损失会沿着一条幂律曲线下降。

但要注意，涌现并不意味着“越大越好”。近几年的研究发现，超过某个规模后，单纯堆参数的边际收益会递减。

所以现在的趋势是：**参数不一定要最大，但数据要足够多，算力也要投入到位。**

## 四、这场转变对工程团队意味着什么

BERT 是判别式模型：输入文本，输出标签；理解和生成是分开的。

LLM 则是输入文本，输出更多文本；理解和生成在同一个模型里完成。这是范式上的根本变化。

现在做 NLP 项目，工作方式已经从「先拆任务，再选模型」，变成了「先想 Prompt 怎么写」。

**现在，LLM 工程师的核心技能是 Prompt Engineering、RAG 系统设计、Agent 编排与对齐微调。**
