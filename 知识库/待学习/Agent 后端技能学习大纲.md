

适用岗位：Agent 应用／全栈工程师、Agent 平台／基础设施工程师。

这份大纲围绕“Agent 在什么场景下需要哪些后端能力，以及具体学什么技术”组织。同类技术先选一种实践，重点掌握它解决的问题与能力边界。

## 一、后端服务开发

**解决什么问题：** 将 Agent 封装为服务，供前端或其他系统调用，支持提交任务、查询结果和实时展示进度。

- **服务框架：** Python + FastAPI，或 TypeScript + NestJS／Fastify。
- **通信：** HTTP、REST API、SSE、WebSocket。
- **异步编程：** async/await、事件循环、线程／进程、连接池。

## 二、数据存储与状态管理

**解决什么问题：** 保存会话、任务进度、工具调用和执行结果，使 Agent 在刷新页面、切换服务器或服务重启后仍能找回状态。

- **关系数据库：** PostgreSQL／MySQL、SQL、索引、事务。
- **缓存：** Redis。
- **执行状态：** 状态机、Checkpoint。
- **文件存储：** S3 兼容对象存储。

## 三、异步任务与工作流

**解决什么问题：** Agent 任务运行较久或需要人工审批时，让任务在后台执行，并支持排队、暂停、恢复和失败重试。

- **任务队列：** Celery／BullMQ、RabbitMQ。
- **工作流：** LangGraph、Temporal。
- **执行机制：** Worker、消息确认、重试、死信队列、定时调度。

## 四、分布式与一致性

**解决什么问题：** Agent 部署到多台服务器后，协调共享状态和任务执行，避免同一任务被重复处理、会话更新互相覆盖，或工具重复产生业务操作。

- **架构基础：** 无状态服务、共享存储、负载均衡。
- **一致性控制：** 数据库事务、乐观锁、分布式锁与租约。
- **可靠执行：** 幂等键、消息去重、Outbox、最终一致性。

## 五、高并发与性能治理

**解决什么问题：** 大量用户同时访问，或多个 Agent 并行调用模型和工具时，控制资源消耗，避免服务、数据库或模型配额被耗尽。

- **并发控制：** 异步 I/O、信号量、连接池。
- **流量治理：** 限流、令牌桶、背压、熔断、降级。
- **扩展与验证：** **水平扩容**、缓存、容量估算、k6／Locust 压测。

## 六、模型与工具接入

**解决什么问题：** 统一调用不同模型和业务工具，处理接口差异、超时、配额和故障，并为代码或浏览器执行提供隔离环境。

- **模型接入：** 模型 SDK、模型网关、路由与降级、Token 预算。
- **工具集成：** Function Calling、MCP、OAuth。
- **执行环境：** 子进程、Docker、沙箱、资源限制。

## 七、知识库与检索服务

**解决什么问题：** 为 Agent 提供可持续更新的业务知识，支持文档上传、检索、更新和删除，并保证检索结果符合用户权限。

- **数据管道：** 文档解析、分块、Embedding、异步入库。
- **检索存储：** pgvector／Milvus／Qdrant、Elasticsearch。
- **检索能力：** 混合检索、Rerank、增量索引、权限过滤。

## 八、安全与多租户隔离

**解决什么问题：** 多个用户或企业共用 Agent 平台时，确保数据不串用、工具不越权，模型生成的操作也必须经过后端权限检查。

- **身份权限：** Session／JWT、OAuth／OIDC、RBAC。
- **隔离机制：** 租户 ID、数据库行级权限、资源配额。
- **安全控制：** 密钥管理、最小权限、审批、审计、提示注入与 SSRF 防护。

## 九、部署、监控与质量保障

**解决什么问题：** 将 Agent 稳定上线，定位任务缓慢或失败的原因，并在升级、扩容和故障后维持服务。

- **部署：** Linux、Docker、Nginx、Kubernetes、CI/CD。
- **可观测性：** OpenTelemetry、Prometheus、Grafana、Langfuse。
- **质量与恢复：** Agent Evals、故障注入、灰度发布、回滚、备份恢复。

## 两个容易混淆的概念

- **分布式与一致性**关注：多台机器共同处理任务时，状态和业务操作是否正确。
- **高并发与性能治理**关注：大量任务同时进入时，资源是否够用、延迟是否可控、过载时如何处理。

它们会一起出现，但需要分别设计。

## 建议学习主线

后端服务 → 数据存储 → 异步任务 → 分布式一致性 → 高并发治理 → 模型与工具接入 → 安全与部署。

知识库按项目需要加入，监控和测试贯穿整个过程。同类框架先选一个实践，避免同时学习多种解决相同问题的技术。
