
## 一、两分钟项目介绍

Serena 是一套围绕 LSP构建的、**领域专精**的代码语义检索与编辑工具集，外加项目配置管理、记忆持久化、多种协议接入层（MCP/CLI/Dashboard）。它自己不具备"调用 LLM、跑对话循环"的能力。

Serena 的 Agent 能力由 Agno 框架补充，Agno跟 LangChain/AutoGPT 这类框架同类型的开源 Python 库，提供的是**跟具体业务领域无关的 Agent 基础设施**，包括：LLM 调用循环、对话历史持久化 (SQLite)及将 Agent 包装为一个 http 服务器等等

**LSP 是协议规范（合同），语言服务器是遵守这份合同的服务端程序（每种语言一个），Serena 是这份合同的一个客户端实现（消费方）**。LSP 本身**不含任何代码解析逻辑**，它只是规定了消息长什么样、怎么编号、怎么应答


Serena 的核心是自己实现了一层 LSP 客户端框架，在这之上包了一套面向 Agent 的符号抽象工具，例如：find_implementations（查找符号的实现）、find_declaration（查看符号声明）等工具，将 IDE 级别的符号分析能力赋予 LLM，进而实现高效符号索引。



## 二、记忆存储机制

**存储分类**：
- 全局记忆：`global/` 前缀的记忆存在用户级目录下
- 项目级记忆：`<project>/.serena/memories/*.md`

**存储原理**：
- 每条记忆是一个 `.md` 文件，可以用 `/` 分层组织成主题/文件夹（如 `frontend/debugging`）
- 记忆之间可以用 `` `mem:xxx` `` 语法互相引用，形成一张"渐进式发现"的知识图谱——agent 先看 `core.md`（图的根节点），再按引用逐步深入到具体主题
- 支持 read-only 记忆（工具上下文中不可写）、ignored 记忆（完全从列表/读写中排除）等访问控制
