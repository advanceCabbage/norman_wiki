### 一、 两分钟项目介绍
我所在的团队是美团标准 API 组，属于美团基建团队负责研发并提供 android、iOS、harmony、H5 等方向的 API 能力，服务于美团内部所有研发团队，包括但不限于美团、点评、外卖等。服务研发人数 1000+，团队内存在大量工单咨询压力，基于这个背景构建了团队智能客服助手，帮助团队减少每日减少工单体感耗时 0.4 PD。

## 二、智能客服的底层框架是什么
底层 Agent 框架、编排流程是由公司内统一基建团队搭建，采用的是工作流编排形式。业务方团队可结合业务属性灵活编排流程、构建知识库及检索策略。在我们团队智能客服流程编排上采用了如下的流程设计：
- **首先**依据用户输入关键字判断走代码检索分支 还是知识库检索分支
- **然后**代码检索分支先小模型 agent判断用户传入的信息是否足够，即是否传入 API 名称和对应端，假设必须信息不足则礼貌要求用户补充，充足则从用户 query 中提取 API 名称和对应端
	- **接下来** API 名称、端（例如：iOS）及用户问题传入 「http 请求节点」
	- 「http 请求节点」内调用服务端接口，触发 Claude SDK 进行代码级的任务分析
	- 将返回的检索任务再返回给用户
- **其次**走知识库检索分支
	- **首先**调用知识库节点进行混合检索，分别获取向量检索+关键词检索各 20 个片段
	- **接下来**采用并集去重 + RRF（倒数排序融合）获得前 20 个片段
	- **最后** Agent 基于 20 个文档片段进行问题回复
## 三、 如何实现文档更新与并集去重
#### 3.1 并集去重原理

- **切块的场景**：混合检索检索到内容片段后通过 chunkIndex 进行区分。使用分段和语义切割的内容均按照**混合检索策略**存储，因此他们相同切块的 chunkIndex 是一致的，这样可以去重
- **FAQ 的场景**：具备 faq_id 字段作为唯一标识

#### 3.2 向量数据如何更新
- **第一学城类文档且是自动更新机制**：按照学城文档的链接作为 document_id，每天定时 12 点定时获取已入库的学城文档是否定时更新，存在更新时会按照当前文档既定策略（按段落、按语义）重新 embedding，实现自动更新并删除历史的向量数据库中旧文档
- **第二类 FAQ 内容格式的更新**：
	- 首先，我们会对每个API 文档调用大模型进行摘要总结
	- 然后，调用知识库提供的 API 进行向量化存储，其中摘要会被向量化，API 原文会全量存储，并传入业务线+API 名称作为唯一标识
	- 后续，后台系统监听到 API 文档变化时，会触发定时任务，对 API 文档再次进行摘要总结并且调用知识库接口进行覆盖式更新
