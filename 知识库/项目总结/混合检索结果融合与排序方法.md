# 混合检索结果融合与排序方法

关键词检索（如 BM25/FTS5）擅长精确匹配术语、文件名和代码标识符；向量检索擅长识别语义相近的表达。**混合检索**的目标是融合两路候选并给出最终排序。

## 1. 分数融合：加权分数相加

**典型方法**：加权线性融合（Weighted Score Fusion）。

**核心思路**：将关键词检索分数和向量检索相似度先转换到相近的数值范围，再按权重相加。设 `s_lex(d)` 为关键词相关性，`s_vec(d)` 为向量相关性：

```text
score(d) = α × norm(s_lex(d)) + (1 - α) × norm(s_vec(d))
```

其中 `α` 的取值在 0 到 1 之间。例如 `α = 0.4`，表示关键词检索占 40%，向量检索占 60%。`norm(...)` 表示归一化，例如 Min-Max 归一化。

**示例**
```text
Chunk A：关键词归一化分数 0.9，向量分数 0.6
Chunk B：关键词归一化分数 0.4，向量分数 0.9

α = 0.5 时：
A = 0.5 × 0.9 + 0.5 × 0.6 = 0.75
B = 0.5 × 0.4 + 0.5 × 0.9 = 0.65
```
因此 A 排在 B 前。

**优势**
- 实现简单，可直接表达业务偏好；
- 两路分数质量稳定时，排序可细粒度调优；
- 可扩展为三路或更多路分数融合。

**劣势**
- **BM25 与向量相似度的量纲不同，必须做好归一化**；
- 不同查询的分数分布可能不同，固定权重不一定始终合适；
- SQLite FTS5 的 BM25 值越小越相关，使用前需要先转为“越大越好”的统一相关性分数。

## 2. 排名融合：倒数排名融合

**典型方法**：倒数排名融合（Reciprocal Rank Fusion，RRF）和 Borda Count。工程中最常用的是 RRF。

**核心思路**：不直接比较两路的原始分数，只关心每个结果在各自检索列表中的名次。RRF 的公式为：
```text
score(d) = Σ 1 / (k + rank_i(d))
```

`rank_i(d)` 表示文档 `d` 在第 `i` 路检索中的名次，`k` 是平滑常数，常用值为 60。名次越靠前，贡献越大；同时出现在多路结果中的 chunk 会累计得分。

**示例**
```text
Chunk A：关键词检索第 2 名，向量检索第 5 名
k = 60

score(A) = 1 / (60 + 2) + 1 / (60 + 5)
         ≈ 0.0315
```

**优势**
- **无需校准 BM25 与向量相似度，适合异构检索器**；
- 对某一路异常分数不敏感，稳定性较好；
- 同时被两路召回的结果会自然靠前。

**劣势**
- **丢弃了原始分数的差距信息**；
- `k` 和各路候选数量仍需通过验证集调优；
- 仅靠排名无法判断“第一名是否远优于第二名”。

## 3. 结果集融合：并集去重与固定配额

**典型方法**：并集去重（Union + Deduplication）、固定配额（Quota Fusion）和优先级拼接。

**核心思路**：**两路检索各自返回固定数量的候选，合并后根据文档 ID 或 chunk ID 去重**。例如关键词检索取 Top-20，向量检索取 Top-20：

```text
candidates = dedupe(Top20_lex ∪ Top20_vec)
```

固定配额则明确规定最终候选的来源比例，例如保留 10 条关键词结果和 10 条向量结果。

**示例**
```text
关键词 Top-3：A、B、C
向量 Top-3：B、D、E

合并去重后：A、B、C、D、E
```

**优势**
- 实现成本最低，能快速提升两路召回覆盖率；
- 不要求分数可比；
- 固定配额可确保关键词检索和向量检索都保留一定机会。

**劣势**
- 本身不产生可靠的统一相关性排序；
- 拼接顺序或配额会直接影响结果；
- 通常需要后续的 RRF、加权融合或重排序补足排序质量。

## 4. 重排序融合：Cross-Encoder 或 LLM Rerank

**典型方法**：Cross-Encoder 重排序、Rerank API、LLM 重排序。

**核心思路**：先用关键词检索和向量检索快速召回较小的候选集，**再让统一的重排序模型同时阅读“查询 + 候选 chunk”，重新计算相关性：**

```text
score(d) = reranker(query, d)
```

这一步不必沿用 BM25 或向量距离，而是由重排序模型直接判断候选是否真正回答了查询。

**示例**

```text
查询：如何创建用户？
候选 A：createUser 的函数实现
候选 B：updateUser 的函数实现

Reranker(A) = 0.95
Reranker(B) = 0.41
```

最终 A 排在 B 前，即使 B 在某一路初始召回中的排名更高。

**优势**
- 通常能显著提升最终 Top-K 的精度；
- 可统一比较来自不同检索路线的候选；
- 擅长处理关键词相同但语义意图不同的情况。

**劣势**
- 计算成本和延迟高于直接检索；
- 只能处理较小候选集，不能直接对全库重排；
- 使用云端模型时需要额外 API 成本与数据合规评估。

| 模型                           | 代码检索 | 文档检索 | 定位                               |

## 5. 学习式融合：Learning to Rank

**典型方法**：逻辑回归、LambdaMART、XGBoost Ranker 和神经网络排序模型。

**核心思路**：使用历史点击、人工标注或任务成功率训练排序模型。模型可以同时接收 BM25 分数、向量相似度、RRF 分数、文件路径命中、chunk 长度、时间新鲜度等特征：

```text
score(d) = fθ(
  bm25(d),
  vector_similarity(d),
  rank_lex(d),
  rank_vec(d),
  path_match(d),
  chunk_length(d)
)
```

模型通过训练学习参数 `θ`，而不是人工指定固定权重。
**示例**

对于“搜索 API 定义”场景，训练数据可能显示：路径命中和关键词精确命中比语义相似度更重要；对于“询问功能实现原理”场景，向量相似度和重排序分数可能更重要。学习式模型可以自动学习这类差异。

**优势**
- 在有高质量训练数据时，通常能达到最高排序效果；
- 能融合多种特征，且不局限于两条检索路线；
- 可以针对具体业务目标持续优化。

**劣势**
- 需要点击日志、人工标注或其他可靠监督信号；
- 训练、评估、部署和监控成本高；
- 数据分布变化后需要重新训练，且要防止训练数据偏差。

## 6. 实际工程中常见的流程

常见做法是让快速检索负责“尽量别漏”，让重排序负责“把前几名排准”：

```text
用户查询
  ├─ 关键词检索（BM25/FTS5）→ Top-20
  └─ 向量检索（Embedding） → Top-20
             ↓
      并集去重 + RRF 融合
             ↓
         候选集 Top-20
             ↓
    Cross-Encoder / Rerank API 重排序
             ↓
         最终返回 Top-K
```

没有重排序模型时，RRF 是常见默认选择，因为它不需要校准异构分数。若两路分数经过验证可以稳定归一化，可改用加权分数融合；积累了足够的标注和日志后，再考虑学习式排序。
