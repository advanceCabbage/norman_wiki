#### SQLite 适合本地轻量一体化；PostgreSQL + pgvector 适合绝大多数业务系统的一库方案；Milvus 适合向量检索成为核心负载、需要大规模和高并发时

| 数据库                        | 向量存储 / 检索                                                                                 | 原文与业务数据存储                                                              | 最适合的场景                                        |
| -------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------- |
| SQLite（配向量扩展 SQLite vec 1） | **轻量、嵌入式、无需独立服务，适合本地或单机小规模检索**；但分布式、高并发和超大索引能力弱。SQLite 官方 `vec1` 扩展可做 L2 / 余弦的 ANN 检索     | 很适合保存原文、元数据、会话记录、配置等；一个 `.db` 文件，备份和随应用分发很方便。                          | 离线应用、桌面端/移动端 AI、个人知识库、PoC、小团队内部工具。openclaw 场景 |
| PostgreSQL + pgvector      | 向量与 SQL、事务、权限、关联查询结合得最好；支持精确检索及 HNSW、IVFFlat 近似索引。缺点是向量规模和查询压力持续升高时，需要更认真地调索引、内存、分区与扩展方案。 | 三者中最均衡：适合存完整文本、用户、权限、文档版本、标签、结构化字段和 JSONB，并能在同一事务中维护原文与 embedding 一致性。 | 大多数生产 RAG、SaaS、企业知识库、需要权限过滤/多租户/复杂业务关联的应用。    |
| Milvus                     | 专为向量检索设计，擅长大规模 ANN、多向量字段、标量过滤和高吞吐；需要单独部署和维护索引、存储及集群组件                                     | 可以存短文本和元数据字段，也可以随检索结果返回；但它不是通用关系型业务数据库，不适合承载复杂事务、频繁关联查询、文档版本关系或核心业务数据。 | 大规模语义搜索、图片/音视频检索、推荐召回、向量是主业务且检索压力很高的系统。       |
HNSW 的英文全称是 **Hierarchical Navigable Small World**，常见中文译法是 **分层可导航小世界图**它是一种用于**近似最近邻（ANN）搜索**的图索引算法，常用于向量数据库中快速寻找最相似的向量。

| 架构                         | 向量放哪                    | 原文放哪                                      | 检索能力与适用性                                                      |
| -------------------------- | ----------------------- | ----------------------------------------- | ------------------------------------------------------------- |
| SQLite 一体化                 | SQLite 向量扩展表            | SQLite 普通表                                | 原文与向量都在一个本地文件；可做语义检索。适合离线、本地、小到中等规模知识库。                       |
| PostgreSQL 一体化             | PostgreSQL + `pgvector` | PostgreSQL 表 / JSONB / 对象存储引用             | 向量检索、全文检索、事务、权限和业务关联都可在一套系统完成。适合大多数业务型 RAG。                   |
| Milvus 一体化                 | Milvus 的稠密/稀疏向量字段       | Milvus 的 `VARCHAR` / `TEXT` 字段            | 可存原文并直接返回；支持稠密向量语义检索、BM25 全文检索及混合检索。适合以检索为核心的知识库、推荐或多模态系统。    |
| Milvus + PostgreSQL / 对象存储 | Milvus                  | PostgreSQL 保存业务原文与关系数据；或 S3 / MinIO 保存大文件 | Milvus 保存用于检索的文本分块副本、向量和元数据；业务系统保留原文主数据。适合大规模、复杂权限、版本管理和审计需求。 |
