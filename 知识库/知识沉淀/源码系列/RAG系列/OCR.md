# OCR、图像描述与图表摘要：图片进入 RAG 前应如何理解

## 1. 背景：它们都是从图片中提取信息的视觉处理结果

当图片进入知识库时，不能只把原图保存起来。系统还需要将图片中的信息转成可检索、可被大语言模型理解的内容。常见产物包括：

- **OCR 文本**：图片上实际写了什么字；
- **图像描述**：这张图片整体表达了什么；
- **图表摘要**：图表中的指标、趋势、比较关系和结论；
- **结构化结果**：表格的行列、表单的键值对、图片中文字的位置与置信度等。

它们都来自视觉处理能力，但底层模型类型并不完全相同：

```text
图片
 ├─ OCR 专用模型              → 可读文字、位置、置信度
 └─ 视觉语言模型（VLM）        → 图像描述、图表摘要、语义解释
```

因此，“都是视觉模型的产物”可以作为宽泛理解；更准确地说，**OCR 是以文字转写为目标的视觉识别能力，图像描述和图表摘要是以图像语义理解为目标的视觉语言能力。**

## 2. OCR 是什么

OCR 是 _Optical Character Recognition_（光学字符识别）。它的目标是将图片、扫描件或截图中的可见文字，转换为机器可处理的文本。

例如，原图中显示：

```text
Milvus 支持 HNSW、IVF 和 DiskANN 索引
```

OCR 的主要输出是：

```text
Milvus 支持 HNSW、IVF 和 DiskANN 索引
```

较完整的 OCR 结果还会包含**文字在图片中的位置**及**识别置信度**：

```ts
{
  text: "Milvus 支持 HNSW、IVF 和 DiskANN 索引",
  boundingBox: [x1, y1, x2, y2],
  confidence: 0.98,
}
```

OCR 的核心问题是“**图上写了什么**”，而不是“这张图想表达什么”。它通常不会可靠地解释图表趋势、流程关系或照片场景。

## 3. OCR 由什么产生

OCR 由 OCR 引擎或 OCR 模型产生。典型处理过程如下：

```text
原始图片
  ↓
图像预处理：去噪、纠偏、裁剪、增强清晰度
  ↓
文字区域检测：找出标题、段落、表格单元格、印章等文字区域
  ↓
文字识别：把每个文字区域识别为字符或词
  ↓
版面恢复：尽量还原阅读顺序、段落、表格、栏位
  ↓
OCR 输出：文本 + 坐标 + 置信度 + 可选布局信息
```

传统 OCR 系统通常由**文字检测模型和文字识别模型**组成；现代文档解析服务还会加上版面分析、表格识别、表单键值对识别和阅读顺序恢复。

对于 RAG，OCR 最重要的价值是把图片中的**精确字词**变成文本。例如：产品编号、日期、金额、报错信息、接口名称、代码片段、专有名词和表格单元格。

## 4. 常见支持 OCR 的模型或服务

以下两个选择具有代表性，分别对应本地开源模型与云端 OCR 服务：

| 选择                      | 公司        | 类型                  |
| ----------------------- | --------- | ------------------- |
| PaddleOCR               | 百度（Baidu） | 开源 OCR 模型与工具链，可本地部署 |
| Google Cloud Vision OCR | Google    | 云端 OCR 服务           |

### 4.1 PaddleOCR：百度（Baidu）

专用 OCR 的目标是尽可能正确地识别文字，并输出文字坐标、阅读顺序和置信度。它们往往支持中文、多语言、倾斜校正和批量处理。
### 4.2 Google Cloud Vision OCR：Google

Google Cloud Vision OCR 是 Google 提供的云端 OCR 服务。它可输出整段文字、单词及其坐标；其中 `DOCUMENT_TEXT_DETECTION` 面向密集文档文字。

### 4.3 视觉语言模型能否替代 OCR

视觉语言模型可以读取图片文字、生成图像描述，并根据提示生成图表摘要，因此它覆盖的任务范围最广。但它并不是在所有场景下都应替代专用 OCR：

- 对错误码、金额、日期、编号、合同条款、代码片段等**精确文本**，优先使用 OCR；
- 对照片、示意图、流程图、架构图等需要解释整体关系的内容，使用视觉语言模型；
- 对图表，使用 OCR / 表格结构提取拿到坐标轴与数值，再让视觉语言模型总结趋势；关键数值仍应回到原图或结构化数据核验。

## 5. OCR、图像描述与图表摘要的对比

| 维度       | OCR                      | 图像描述                   | 图表摘要                   |
| -------- | ------------------------ | ---------------------- | ---------------------- |
| 核心目标     | 转写可见文字                   | 描述图片整体语义               | 解释图表中的数据关系与结论          |
| 典型模型     | OCR 引擎、文字检测/识别模型         | 视觉语言模型                 | 视觉语言模型，必要时结合 OCR 和表格解析 |
| 典型输出     | `HNSW`、`2025 年营收`、报错堆栈   | “一张 Milvus 检索架构图”      | “Q4 营收最高，较 Q1 增长 32%”  |
| 强项       | 精确关键词、编号、文本内容            | 场景、对象、布局和整体含义          | 趋势、比较、峰值、异常和业务结论       |
| 主要风险     | 模糊、倾斜、手写、复杂版面导致错字或阅读顺序错误 | 过度概括、遗漏细节，甚至生成与图片不符的描述 | 误读坐标轴、图例、单位或具体数值       |
| 是否适合精确问答 | 适合，例如“图片中出现了哪些索引名？”      | 不应单独依赖                 | 不应单独依赖，应回看图表或结构化数据     |

### 示例：同一张架构图的不同输出

假设图片是一张 RAG 架构图，画面文字为：

```text
用户问题 → Embedding 服务 → Milvus → Top K 片段 → LLM
```

OCR 输出：

```text
用户问题
Embedding 服务
Milvus
Top K 片段
LLM
```

图像描述输出：

```text
这是一张 RAG 检索流程架构图。用户问题先被转换为向量，
随后在 Milvus 中检索 Top K 相关片段，最后由 LLM 基于片段生成回答。
```

两者没有替代关系：OCR 保留了 `Top K`、`Milvus` 等精确术语；图像描述补全了箭头所表达的处理顺序和整体逻辑。

## 6. 各自适用的场景

### 6.1 优先使用 OCR 的场景

- 扫描件、合同、发票、表单和证件；
- PPT、网页或代码截图；
- 包含大量可读文字的图片；
- 需要按产品编号、日期、金额、错误码、专有名词精确检索；
- 需要将表格文字转成可搜索内容。

### 6.2 优先使用图像描述的场景

- 商品图、现场照片、设计稿；
- 流程图、架构图、示意图；
- 图片中文字很少，但视觉布局或对象关系很重要；
- 用户会提出“找一张展示某个场景/结构/风格的图”这类问题。

### 6.3 优先使用图表摘要与结构化提取的场景

- 折线图、柱状图、饼图、仪表盘；
- 需要回答趋势、同比、峰值、异常点等问题；
- 需要精确读取坐标轴、单位、图例和数值时。

图表不能只依赖自然语言摘要。较稳妥的做法是同时保存：原图、OCR 文本、图表摘要，以及可提取时的结构化数据（例如 CSV 或 JSON）。

## 7. 用于 RAG 的推荐组合

不建议只选择 OCR 或图像描述其中之一。一个图片知识条目可以设计为：

```ts
{
  imageUrl: "images/milvus-architecture.png",
  ocrText: "用户问题 Embedding 服务 Milvus Top K LLM",
  description: "一张 RAG 向量检索流程架构图",
  chartSummary: undefined,
  source: "rag-guide.pdf",
  page: 8,
  headingPath: ["RAG", "检索流程"],
}
```

随后将 `ocrText`、`description`、图表摘要以及标题上下文拼接成文本，用文本 Embedding 建立可检索索引；原图地址则作为检索结果的证据和展示内容保留。

```text
用户问“图中提到了哪些数据库？”
  → OCR 更可靠，因为需要精确找出 “Milvus”。

用户问“是否有展示 RAG 检索流程的架构图？”
  → 图像描述更可靠，因为需要理解整张图的主题。
```

如果还需要按视觉语义直接找图，例如“找一张带箭头的蓝色系统架构图”，则应在上述文本处理之外，再增加多模态图片向量索引。

## 8. 总结

OCR 是“**读出图片里的字**”；图像描述是“**理解图片整体表达的意思**”；图表摘要是“**解释图中的数据关系和结论**”。

对于图片 RAG：

```text
精确文字检索 → OCR
主题与视觉语义检索 → 图像描述 / 多模态图片向量
数值趋势与业务结论 → 图表摘要 + 结构化数据
```

三者结合，才能既检索得准，又让回答能回到原图进行核验。
