# 多模态同空间嵌入技术文档

## 1. 一句话解释

**多模态同空间嵌入**是指用一个模型,把不同模态的数据(如图片、文本,也可扩展到音频、视频)分别编码成向量,并且让这些向量落在**同一个语义坐标系**里——于是"一张图"和"描述它的一句话"会天然地挨得很近,可以直接用向量距离(通常是余弦相似度)跨模态比较,**从而实现"用文字搜图、用图搜文、以图搜图"这类跨模态检索**

---

## 2. 核心原理:为什么能"同空间"

关键机制是 **双塔架构(dual-encoder / two-tower)+ 对比学习(contrastive learning)**,以 CLIP(Contrastive Language–Image Pre-training，对比语言图像预训练)为开山代表。

### 2.1 双塔结构

模型内部是两个相互独立的编码器,各管一种模态,但**输出到同一个维度的向量空间**:

```
   图片 ──▶ [图像编码器 Image Encoder] ──▶ 图向量 Vi  ┐
                                                      ├─▶ 同一个 d 维空间(如 512/768/1024)
   文本 ──▶ [文本编码器 Text  Encoder] ──▶ 文向量 Vt  ┘
```

- 图像编码器通常是 ViT(Vision Transformer，视觉 Transformer)或 CNN（Convolutional Neural Network,卷积神经网络）;
- 文本编码器通常是 Transformer;
- 两塔的输出向量一般会做 **L2 归一化**,让"点积 = 余弦相似度"。
	- **点积 = 向量长度 × 余弦相似度**
	- **L2 归一化就是把"长度"这个因素去掉,于是点积直接等于余弦相似度**
	- **L2 归一化**把向量**除以自己的长度**,得到一个长度恰好为 1 的同方向向量

### 2.2 对比学习:让配对的靠近、不配对的远离

训练数据是海量的 **"图片—配文"成对样本**(例如一张金毛犬照片配 "一只金毛犬")。

一个训练批次里取 N 对图文,两两组合算相似度,得到一个 N×N 的相似度矩阵:

```
              文1   文2   文3  ...  文N
        图1 [ ✓    ·    ·   ...  ·  ]   ← 对角线是"正确配对"(正样本)
        图2 [ ·    ✓    ·   ...  ·  ]
        图3 [ ·    ·    ✓   ...  ·  ]      非对角线是"错误配对"(负样本)
        ...
        图N [ ·    ·    ·   ...  ✓  ]
```

训练目标(常用 **InfoNCE / 对比损失**):

- **拉近**对角线上的正样本(图与它自己的配文);
- **推远**所有非对角线的负样本(图与别人的配文)。

当**这个目标在亿级图文对上收敛**后,就产生了一个奇妙的性质:

> **一张图的向量,和"能描述它"的那句话的向量,会自动挨得很近——即使模型在推理时从没为这张图生成过任何文字。**

因为两个塔是被"同一把尺子(相似度)"一起优化的,它们被逼着把"语义相同的东西"放到坐标系里相同的位置。这就是"同空间(shared / joint embedding space)"的来源:**图片和文字不再是两套互不相通的编码,而是同一坐标系里的点**。

### 2.3 与"视觉对话模型"的区别(易混点)

- **多模态嵌入模型(本文主角)**:图/文 → **可比对的向量**,用于检索。
- **视觉语言对话模型(VLM,如 GPT-4V 类)**:图 → **一段文字回答**,用于"看图说话/问答",它本身不直接产出用于检索的同空间向量。

二者常被混为一谈,但用途完全不同:要做跨模态**检索**,需要的是前者。

## 3. 用什么模型解析

需要的是**带图像塔的多模态嵌入模型**,分开源自托管与云 API 两类。

### 3.1 开源 / 可本地部署

| 模型                    | 特点                              | 常见维度             |
| --------------------- | ------------------------------- | ---------------- |
| **CLIP**(OpenAI)      | 开山之作,英文语义强                      | 512 / 768        |
| **OpenCLIP**          | CLIP 的开源复现与扩展,权重丰富              | 512 / 768 / 1024 |
| **SigLIP**(Google)    | 用 sigmoid 损失替代 softmax,小批量也能训得好 | 768 / 1152       |
| **Chinese-CLIP**(达摩院) | **中文原生训练**,中文文搜图效果好             | 512 / 768        |
| **Jina-CLIP v2**      | 多语种(含中文)、支持较长文本                 | 1024             |
| **BGE-VL**            | 面向检索优化的图文嵌入                     | 视版本而定            |

### 3.2 云 API

- **Cohere Embed v4**、**Voyage multimodal**、**Jina Embeddings**、**Google 多模态嵌入** 等,均提供"图/文 → 同空间向量"的接口,免运维,但按量计费、数据出网。

### 3.3 选型要点

- **语言**:中文语料优先看中文原生或多语种模型(Chinese-CLIP、Jina-CLIP v2);
- **维度**:决定了向量库该建多少维,后面存储要对齐;
- **文本长度上限**:部分 CLIP 类模型文本端只吃 ~77 个 token,长 query 会被截断,需选支持长文本的变体;
- **本地 vs API**:本地可控、无出网,但要 GPU 与运维;API 省心但有成本与合规考量。

## 4. 用什么向量库存储

同空间嵌入产出的就是**一串定长浮点数**,因此**任何主流向量库都能存**:FAISS、Milvus、Qdrant、Weaviate、pgvector、Chroma、LanceDB 等。真正要注意的是下面几点。

### 4.1 维度必须与模型对齐

向量列/集合的维度必须**等于所选模型的输出维度**(512 就建 512,1024 就建 1024)。维度一旦建库就固定,换模型往往要重建。

### 4.2 图文可以共存于同一集合

- CLIP 图向量 ＋ **CLIP** 文向量 ，在**同一空间**,它们**可以放进同一张表/同一个索引**里一起检索
- CLIP 图向量 ＋ **embedding-3** 文向量，**不在同一空间**，不允许在同一张表中，不允许一起检索，相似向量无意义

### 4.3 相似度度量

- 通常用 **余弦相似度(cosine)**;若向量已 L2 归一化,用**内积(dot product)**等价且更快;
- 建库时的度量方式要与检索时一致。

### 4.4 元数据(metadata)存原物引用

向量本身不含原始内容。常见做法是把**原始资产的引用**(图片路径 / URL / 对象存储 key、文本原文或其定位信息)连同向量一起存为 metadata,命中后据此取回真正要展示的图或文。

### 4.5 索引方式

数据量大时用近似最近邻(**ANN**)索引加速,如 **HNSW**、**IVF(+PQ)** 等,在检索速度和召回率之间权衡。

---

## 5. 检索方式

同空间嵌入的核心红利,是**跨模态检索**:query 和被检索对象可以是不同模态,只要都编码到同一空间即可比距离。

### 5.1 文搜图(text → image,最常用)

1. 把用户的文字 query 用**模型的文本塔**编码成向量 `Vq`;
2. 到**图片向量索引**里做余弦 top-k;
3. 返回最相近的图片(经 metadata 取回原图)。

> 亮点:全程**不需要事先给图片写任何描述**——模型直接理解图片语义,能命中"文字很难提前描述清楚"的视觉细节。

### 5.2 以图搜图(image → image)

query 换成一张图,走**图像塔**编码,再到图片索引里找相似图。用于去重、找同款、找相似场景。

### 5.3 图搜文(image → text)

用一张图去检索**文本库**,召回语义相关的文字段落(如给图片自动匹配说明、找相关文档)。

### 5.4 统一跨模态检索(unified)

若把文本和图片**都编码进同一索引**,一次检索即可**同时召回相关文字与相关图片**,再按分数统一排序。适合"混合结果页"。

### 5.5 检索流程要点

- **查询编码要用"对应的塔"**:文字 query 走文本塔,图片 query 走图像塔——两者输出在同一空间,才能互相比对;
- **度量一致**:检索用的相似度(cosine / 内积)要与建库时一致;
- **归一化一致**:若建库向量做了 L2 归一化,query 向量也要归一化;
- **top-k 与阈值**:取前 k 个,或叠加相似度阈值过滤弱相关;
- **可与重排结合**:粗召回(ANN top-k)后可接更精细的重排模型进一步排序。

## 附:一图总览

```
                     ┌─────────────────────────────────────────┐
   建库阶段           │            同一个 d 维向量空间             │
   图片集 ─[图像塔]─▶ │   · 图a   · 图b        · 文x             │
                     │        · 图c    · 文y      · 文z          │  ← 语义相近的
   文本集 ─[文本塔]─▶ │   · 文w             · 图d                │     图与文彼此靠近
                     └─────────────────────────────────────────┘
                                        ▲
   检索阶段                              │ 余弦 top-k
   文字/图片 query ─[对应塔]─▶ 查询向量 ─┘
```

**一句话收束**:多模态同空间嵌入用"双塔 + 对比学习"把不同模态压进同一坐标系,于是"存"用普通向量库即可,"检"则解锁了文↔图的自由跨模态检索。
