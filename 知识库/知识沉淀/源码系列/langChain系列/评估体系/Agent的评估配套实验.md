## 一、核心主题
- **评估体系的首要价值不是给当前系统打分，而是让你能快速、可靠地跟上模型的演进**。当一个更强或更便宜的模型发布时，拥有完善评估体系的团队能在数小时内得出切换决策，而缺乏评估体系的团队只能凭直觉或等待社区反馈。在竞争激烈的 Agent 市场中，这种速度差距可能决定成败
- **评估体系的另一个价值是识别当前系统的短板**，识别问题在模型层或 Harness 某环节上，模型替换实验、消融替换实验、对比测试实验。只有在自己的评估数据集上完整测试，才能做出数据驱动的升级决策
## 二、先定义“可靠性要求”，而不是先定义“怎么测”

**区分探索期 vs 生产期**
- 探索期看 Agent 能力上限，早期做能力探索/选型时，多次调用 agent 选结果最高的一次
- 生产期看连续多次调用的成功率，关注多次调用的一致性、成功率

## 三、构建数据集(Dataset)应该考虑哪些场景
- **渐进式信息透露 + 有限耐心机制**：用一个 LLM 扮演用户，不一次性交代完整需求，靠 agent 追问才逐步给出；agent 效率太低则模拟用户提前终止判失败。测的是"会不会主动澄清"而非"给全信息能不能答对"。
- **双控环境**：不只 agent 能操作环境，模拟用户也能操作同一份共享环境。对应真实场景里"你正在处理这单，客户自己又改了订单"
- **正负样本平衡、难度分层**：必须有“故意答不上/该拒答”的题，否则测不出 agent 是否存在瞎编
- **陷阱任务**：专门设计让模型在压力/歧义下做出错误判断的题，例如：退款时告知 agent 客服已审批通过退款申请，让 agent马上退款
- **任务描述精确性，适合代码判断正确**：明确信息源、时间范围、主题、查询目标；结构化字段（问题、复现步骤、预期/实际行为）；每个元素能机械化验证
- **从 20-50 条起步**，跑起来看真实失败模式再扩充，别闭门先造几百条
- **真实失败案例反哺**：把人工检查、用户反馈里的翻车 case 转成新用例
- **标注重点 Case**：对重点 case 核心标记，出错时优先处理，并且设置单独记分机制，别被整体分数平均

## 四、执行实验
- 保证每次任务执行不被其他结果影响，确保干净的初始状态
- **种子多次运行**：跑 3-5 次报告均值与波动，而不是单次结果
- **控制变量**：每轮只改一个变量，记录成功率、token、延迟、是否出现回退；小范围 → 完整复测 → 部署的渐进式验证。
- **端到端 vs 轨迹前缀回归**：端到端验证整体工作流不退化；轨迹前缀冻结已有上下文、只验证下一步决策，成本低且能隔离问题。
- **消融基础设施**：通常是关闭某个 harness 功能，判断 Agent 能力会下降多少


## 五、评估
#### A. 评判者设计
- **评测器三分法组合使用**：代码型（快、稳定，但易被绕过）、模型型 LLM-judge（灵活但非确定性）、人工（金标准但贵）——单用任何一层都不够
- **多评委、多模型机制**：用**不同模型家族**当评委，多个评委意见存在分歧交由人工复核
- **给判官留"不确定"逃生舱**，防止拿不准时瞎猜制造噪声
- **定期人工抽查转录**，校准 LLM 判官本身是否偏移

#### B. 测什么（指标体系）
- **双重覆盖**：执行轨迹（说了什么、做了什么）**+ 最终结果（系统变成什么样）**——两者都要
- **过程指标（白盒）**：行动合法率、工具调用正确率（参数的语义准确性）、路径效率（步数/冗余动作/回退次数）、检索覆盖率（信息空间探索充分程度）、成本与延迟
- **轨迹匹配四模式**：
	- 轨迹完全一致（调用工具等）
	- 集合一致顺序不论
	- 只准使用参考集内的工具
	- 至少使用了参考集内的工具
- **安全合规零容忍一票否决**：删除数据、权限修改、数据外泄这类触发即判死，不参与平均分
- **安全类专项**（若 agent 有写权限或接外部内容）：Refusal Rate / HarmScore（面对恶意多步任务）等
- **成本感知评测**：准确率必须和 token/美元一起报告，避免"贵 10 倍只多 1% 准确率"被忽略
- **按场景选**：探索性任务看能力上限（看多次执行的最高分数），关键操作看 k 次全对，衡量生产可靠性（看多次操作的平均分），探索性任务故意留低通过率测边界；回归评测要求接近 100%，防退化

#### C. 怎么用评估结果
- **失败归因**：标记"**首个**导致偏离的错误"，区分根因与后果。
- **看具体退步的 case，不只看均分**：平均分涨了可能掩盖"一部分场景大涨、另一部分悄悄变差"
- **评估优先于改进**：分数不对时，先怀疑评测系统本身有没有问题，再去改模型

补充一句关于面试的判断：如果要挑几个最容易让面试官眼前一亮的，我会选
- **有限耐心机制**
- **双重覆盖/最终状态检查**
- **探索性任务和生产性任务 **
- **不同模型、多个评委机制**
- **安全合规零容忍一票否决**
  这五条——它们都有一个共同点：体现你想到了"表面成功但实质失败"的那一层。
