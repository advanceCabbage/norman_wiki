## 一、总览
评估体系由三部分数据结构组成：数据集（Dataset）、执行实验（Experlment）、评估(Evaluation)

## 二、数据集（Dataset）
数据集本质是一份可以反复使用的“考卷”，每一组数据包含**输入+期望的输出**。后续无论 agent 如何变化都使用这份“考卷”进行测试。
上传数据集方式：
- **本地维护脚本推送**：通过 langSmith 提供的createExamples 等方法推送，后续通过唯一 ID 判断新建或更新单条数据
- **langSmith 网站上手动创建**
两种方式都实际存储在 LangSmith 云端，本地维护便于管理、更新数据集

## 三、执行实验（Experlment）
实验就是让你的系统（检索函数、agent）针对数据集里的每一条 Example 真跑一遍，产生真实输出，每条输出连同它的完整调用过程（trace）会被记成一次 Run，整批 Run 汇总成一个Experiment。
执行方式，支持线上或线下都可
- **线下执行**：在本地真实执行 agent 调用，并把执行结果（包括每一步 trace）上传到 LangSmith 云端保存
- **线上执行**：支持部署 agent 到 LangGraph Platform，也支持按照 LangGraph Server 协议起一个服务
线上执行的方式可以通过 langSmith 操作界面执行实验。

## 四、评估（Evaluation）
评估本质是对执行实验的结果进行评分，评分依赖于数据集中期望结果 + 真实运行的结果。
执行方式，支持线上或线下都可
- **线下执行**：调用本地函数判断关键词或调用 LLM 判断结果，和执行实验的结果同步进行判断
- **线上执行**：在 langSmith 上配置判断方式，支持 LLM as a judge、支持写判断函数完全在云端执行

## 五、可以看到哪些数据
- 选中一条执行实验作为基线，可以自动对比与其他实验指标数据的差异
- 任意选中两条实验，进行对比
- 将工具调用成功作为单独指标查看

## 六、应该看哪些数据
##### 结果指标（黑盒）
- 看每条实验的成功率
- 重复执行多次相同实验看成功率

##### 过程指标（白盒）
- 路径效率：步数、冗余动作、回退次数
- 行动合法率：有效且合法操作的比例
- 工具调用正确率：参数、结果在语义上的准确性
- 检索覆盖率：例如多跳问题，检索是否完全覆盖

##### 失败归因
- 标记首个导致偏离的错误节点，例如是检索没召回还是模型瞎编

##### 安全类指标
- 安全合规零容忍，例如：删除数据、权限修改等只要触发就当作红线处理，不应该被平均

过程指标 langChain 提出的核心概念：Trajectory Match(弹道匹配)，关注以下四种匹配模式：
- **strict**：工具调用顺序必须和参考轨迹完全一致
- **unordered**：工具集合一致，顺序不论
- **subset**：只准用参考集合里的工具（防止乱调用）
- **superset**：至少覆盖参考集合要求的工具（防止漏调用）
