#### 一、工具加载策略

- 先组装候选工具：核心编码工具、OpenClaw 工具、渠道工具、插件工具。
- 再依次应用策略：工具 profile、全局配置、Provider 配置、Agent 配置、群聊限制、沙箱限制、子 Agent 限制、owner-only 限制等。
- 剩余工具的 `name`、`description`、`parameters` 被转换为模型 SDK 的 `customTools`。

OpenClaw 采用“**全量候选、按策略暴露**”模式。模型看到的是最终允许使用的完整工具集合，而不是机器上已安装的全部工具。工具 schema 走模型 API 的 tools/customTools 字段，不是简单拼到 system prompt 里的一大段文本。

#### 二、用户自定义机制

自定义插件工具不是“注册后永远自动可用”；它和内置工具一样，先进入候选集，再经过策略过滤。普通插件工具通常会进入最终工具集；可选工具必须被显式允许。插件注册入口是 `api.registerTool(...)`

自定义工具的“实现”属于插件代码，“启用和参数”属于用户配置，“是否给某个模型使用”由 Agent 工具策略决定；模型只看到函数 schema，不看到实现

#### 三、工具输出过长如何防御
1. **工具本身支持分页或限制输出**
	例如文件读取类工具通常提供 `offset`、`limit` 等能力，避免把一个超大文件一次性交给模型。正确的 Agent 行为是“先读摘要或局部，再按需继续读取
2. **写入会话前有硬上限截断**
	超过 400,000 字符部分直接截断删除，模型后续看到的是“前半部分 + 截断提示”，看不到被截掉的正文尾部
3. **进入下一轮模型上下文前再次裁剪**
	- 单条结果限制；
	- 所有工具结果总预算限制；
	- 过旧输出优先被替换为压缩占位提示
4. **上下文溢出时进行恢复性截断**
	1. 如果模型调用仍然触发 context overflow，运行器可对历史会话中的超大工具结果再做截断并重试，而不是直接让整个 Agent 回合失败。
5. **持久化层还可由插件接管**
	1. `tool_result_persist` 和 `before_message_write` 可在结果真正写入会话前继续脱敏、缩短或拦截。例如企业可以在这里：
		1.  删除 Token、手机号、身份证号；
		2. 将网页全文替换为内部摘要；
		3.  禁止持久化敏感命令输出；
#### 四、汇总
OpenClaw 的工具机制采用插件化注册与策略化暴露。系统先汇总内置、渠道和插件工具，再按全局、Provider、Agent、群聊、沙箱和子 Agent 等策略过滤。过滤后的工具会被规范化为兼容各模型 Provider 的 JSON Schema，并以 `customTools` 形式提供给模型。

工具调用不是直接执行：调用前有 `before_tool_call` 和循环检测，调用后有 `after_tool_call`，结果写入会话前还有 `tool_result_persist` 与 `before_message_write`。

面对长工具输出，OpenClaw 使用工具分页、持久化硬截断、模型上下文二次裁剪和溢出恢复截断等多层防护。因此它既避免模型上下文被日志或网页正文撑爆，也给企业部署留出了脱敏和审计扩展点
