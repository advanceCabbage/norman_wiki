## 一、总览
从 CoT（Chain of Thought 思维链） -> ToT（Tree of Thoughts 思维树） ->  GoT （Graph of Thoughts 思维图）

## 二、CoT

**CoT 能增强推理能力的原因**
模型是一个 token 一个 token 生成的，让它先组织推理步骤，等于给了它一张「草稿纸」，后面生成答案时能利用前面的推理上下文，自然出错就少了

**CoT 存在两种形式**
- **Few-shot CoT**：在 prompt 中给出几个完整的「推理示例」，效果稳定但 Prompt 长
- **Zero-shot CoT**：在 prompt 中添加一句「让我们一步步思考」，简单但效果稍差一点

**CoT 的局限性**
- Token 消耗更大、延迟也会增加
- 对简单问题适得其反，对纯记忆类任务没有帮助
- 推理链路本身也可能出错，一旦走错就全错

**CoT 的增强方式：Self-Consistency**
**首先**，调高 temperature，例如 0.7
**然后**，使用同一个 prompt 调用多次大模型
**最后**，程序收集多次调用中，出现概率最高的一条答案作为最终的答案回复给用户

## 三、ToT

核心改变是把「生成一条推理链」变成「同时探索多条推理路径，边探索边剪枝，最终选出最优路径」

核心步骤的三个步骤：
- **首先**生成多个候选思路，让 LLM 针对同一个问题给出 3 个不同的初步方向，而不是只走一条路
- **然后**评估每个思路的可行性，用另一个 LLM 调用给每个思路打分，判断哪个最有希望
- **最后**选优继续深入、剪掉差的，只保留分数高的思路，再展开下一层推理，反复循环直到得出最终答案


## 四、GoT

GoT 的全称是 Graph of Thoughts（思维图），是在 ToT 基础上再进一步的进化。

ToT 虽然引入了多路径探索，但它是树形结构，不同分支之间完全独立，两条推理路径的中间结论无法相互借用。GoT 把推理结构换成了图，允许不同路径的中间结果合并、复用，也就是说一个推理节点可以接收来自多个前置节点的输出作为输入


## 五、三者的演进关系

CoT 解决了把推理过程显示化，通过将过程写出来显著减少跳步出错问题
ToT 解决了「单次推理走错方向」导致整个推理过程全错的问题
GoT 解决了「不同推理路径的中间结论能不能复用」的问题，答案是把结构从树换成图，自然支持结论汇聚与复用
