文章核心：新一代模型判断力更强，冗长、重复、过度约束的上下文反而可能干扰效果。Anthropic 为 Claude Code 删除了超过 80% 的系统提示词，编码评测没有可测量的下降。[原文链接](https://x.com/trq212/status/2080710971228918066)

- 过去：给模型大量明确规则。  
    现在：让模型结合上下文自行判断。  
    原因：旧模型需用硬规则避免坏结果；新模型更能理解意图。比如不再一刀切禁止注释，而是要求代码的注释密度、命名和习惯贴合现有项目。
    
- 过去：为工具提供操作示例。  
    现在：优先设计表达力强的工具接口。  
    原因：示例会把模型限制在既定探索路径；清晰的参数、枚举值和状态约束本身就能传达正确用法。
    
- 过去：把所有流程和知识预先塞进系统提示词。  
    现在：渐进式披露（按需加载）。  
    原因：代码审查、验证等信息并非每次任务都需要；将其拆为可按需调用的 Skill，能节省上下文并降低干扰。
    
- 过去：系统提示词和工具描述中都重复工具使用说明。  
    现在：只在工具描述中保留说明。  
    原因：新模型能稳定遵守局部、明确的工具定义；重复指令会增加冲突和噪声。
    
- 过去：用 `CLAUDE.md` 充当长期记忆，并手动持续写入。  
    现在：使用自动记忆。  
    原因：系统可自动保存与用户和当前工作相关的信息，减少维护手工记忆文件的成本。
    
- 过去：计划和规格主要写成简单 Markdown 文档。  
    现在：使用更丰富、更高保真的参考材料。  
    原因：模型能够理解 HTML 原型、测试套件、现有代码甚至其他代码库；例如 HTML 设计稿通常比文字描述或截图更明确。
    
- `CLAUDE.md` 的定位变化：  
    过去：作为“所有规则和最佳实践”的总仓库。  
    现在：保持轻量，只写仓库用途和模型无法从代码自行推断的坑点；详细流程放进独立 Skill。 
    原因：显而易见的信息会占用上下文，且可能与其他指令冲突。
    
- Skill 的定位变化：  
    过去：尽量全面、细致地规定模型的执行方式。  
    现在：承载团队/产品特有的知识、偏好和最佳实践，长 Skill 拆分成多个文件。  
    原因：Skill 最有价值的是补充模型不知道的专属上下文，而不是重复通用常识。
    

一句话总结：上下文工程正从“保姆式地规定模型每一步怎么做”，转向“给模型清晰接口、必要约束和可按需检索的专属信息”。
