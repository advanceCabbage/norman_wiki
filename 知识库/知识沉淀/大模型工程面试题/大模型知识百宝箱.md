
## 一、多头注意力的局限性
#### 多头注意力机制存在的问题
- 显存上 KV Cache 随头数和序列线性增长，长上下文场景一下就吃光显存；
- 访存上 Attention 计算反复读写 HBM 大矩阵，瓶颈不在算力在带宽；
- 复杂度上注意力矩阵是 N×N，序列翻倍计算量翻 4 倍

#### 业界的解决方案
- MQA 是暴力共享 K/V，显存压到 1/H 但表达力有损失；
- GQA 是分组折中（Llama 2 70 B、Llama 3、Qwen 2/3 的不少主力模型都用），显存接近 MQA 但效果接近 MHA；
- Flash Attention 走另一条赛道，不改 Attention 结构，从计算实现层面用「分块 + 在线 softmax」把显存从 O(N²) 降到 O(N)，速度还快 2-4 倍。

结构层（GQA）和实现层（Flash Attention）攻击的痛点不同，主流大模型都是 GQA + Flash Attention 同时用。另外 MLA（DeepSeek 用的低秩潜在注意力）作为更前沿的方向。

 **MQA -> Multi-Query Attention**（多查询注意力）
 **GQA -> Grouped-Query Attention**（分组查询注意力）
 **Flash Attention**（快速注意力算法）


## 二、大模型项目的分词器及原理

#### 2.1 为什么需要 Tokenizer？
大语言模型的本质是一个函数：只能接收一串整数（Token ID 序列），输出下一个整数的概率分布，然后把输出的整数再查表得到对应的文字。

Tokenizer 就是把文字转成数字 ID 序列的桥梁

#### 2.2 Tokenizer 对应的算法 BPE
**BPE Byte Pair Encoding，字节对编码**原理很简单，采用的是**子词分词原理**，分三步实现：
- **第一步初始化**：把训练语料里所有文本拆成最小单元（**单个字节或字符**），每个字符就是一个基础 Token，形成初始词汇表
- **第二步反复合并**：统计语料中所有相邻 Token Pair 的出现概率，找到概率最高的那对。就把他们合并，加入词汇表。然后继续找下一个最高频 Pair。例如：「t」和「h」频率最高就合并为「th」，然后下一轮对比时,「th」和「e」频率最高就合并为「the」
- **第三步重复直到词汇表达到预设大小**：各家预设大小不同，训练数据不同则词汇表也不相同，比如 GPT-2 用了 50257，Llama 3 用了 128000

其他分词算法还有：SentencePiece、WordPiece。
另外两种直观的分词方式的缺陷：
- **字符级分词**，会导致词汇表很小，英文才 26 个字母加标点。一篇文章的 token 会大幅飙升且语义太少
- **词级分词**：完整单词算一个 token，遇到没见过的词汇无法处理，中文无法确定应该如何分词
#### 2.3 Tokenizer 的重要性
- **API 成本估算**：1000 汉字大约对应 1000-1500 tokens，1000 个英文单词大约 1300 token
- **上下文窗口管理**

## 三、训练大模型的三个阶段

#### 3.1 预训练是地基
预训练的数据来源于互联网海量的数据，预训练前首先需要对训练数据做大量清洗工作、去重、过滤低质量内容等，高质量的训练集清洗成本可能比模型训练本身更贵，这是模型公司的核心竞争力之一。

预训练的目标是**预测下一个 Token**，每条训练样本就是「给前 N 个 token，预测第 N+1 个 token」，对整个语料库做这件事，反复调整模型参数让它的预测越来越准

预训练之后模型具备预测下一个 Token 能力，能续写问题

#### 3.2 SFT 监督微调
**SFT = Supervised Fine-Tuning，监督微调**

SFT 的目标是：模型能够按照指令回答问题，但可能回答方式不一定是预期的，可能有不该说的话、太啰嗦之类问题

**SFT 是使用大量高质量的问答数据，去训练模型基于指令回复问题的能力**

#### 3.3 对齐

**对齐的目的是让模型的行为更符合人类的价值观和偏好**

常见的对齐方法：
**RLHF -> Reinforcement Learning from Human Feedback**（基于人类反馈的强化学习）
RLHF 由奖励模型 + PPO 组成，奖励模型给大模型回复打分，最后用 PPO 强化学习调整大模型的参数

**DPO -> Direct Preference Optimization**（直接偏好优化）
DPO 不需要奖励模型和 PPO（Proximal Policy Optimization**近端策略优化**），用数学等价的方式改写为纯监督学习

**这三个阶段缺一不可，预训练定天花板，SFT 给格式，对齐给价值观**，大模型公司之间真正的护城河在预训练阶段（数据 + 算力 + 工程经验），SFT 和对齐相对来说技巧已经透明化了


## 四、Scaling Law（缩放定律）

Scaling Law 的本质：模型的损失值（loss）随模型参数 N、训练数据量 D、训练算力 C 这三个量按幂律下降，首次是由 OpenAI 2020 年提出，但未说明具体比例。

DeepMide 在 2022 年提出参数和数据比例接近 1:20 更划算，效果更优。

后续 Llama3 进一步证明 1:20 不是极限，小参数+大量数据的效果更优，在 2024 年后成为重要趋势

Scaling Law 的天花板在于**数据见底**（公开文本数量有限）和**算力瓶颈**（GPU 算力增长缓慢），应对方向包括：纳入多模态数据（图片、视频等）、合成数据（用强模型生成训练数据训练弱模型）

## 五、大模型的参数：温度值、Top-P、Top-K
#### 5.1 Temperature 温度值

**原理**：Temperature 通过缩放 logits 改变 softmax 输出分布的概率，进而影响采样的随机性。通常 Temperature = 0 相当于退化成贪心解码（永远选概率最高的 token）。Temperature 控制输出的随机性，值越低输出越稳定/越集中，值越高输出越发散

Temperature 解决的是「分布的松紧」，但还有另一个维度可以控制采样：候选词的数量。这就是 Top-K 和 Top-P 要解决的问题。

#### 5.2 Top-K 限制候选词的数量

**原理**：每次采用前，把概率分布截断到只保留概率最高的 K 个词，其余全部置为零，然后在这 K 个词里按比例采样

比如 Top-K=50 意味着每一步只从概率最高的 50 个词里选，K 越小越保守；K 越大可选范围越广

**存在的问题** K 是固定的，对不同场景无法自适应

#### 5.3 Top-P 自适应的截断

Top-P 也叫 **Nucleus Sampling**（核采样），它解决了 Top-K「不自适应」的问题。
**原理**按概率从高到低排列所有词，累加概率，当累加值超过阈值 P 时停止，再被选中的词中进行采样

比如 Top-P=0.9，则从概率最高的词开始累加，直到概率累计达到 90%为止

#### 5.4 常规的做法
代码生成或者智能客服问答我会把 Temperature 调到 0~0.2，Top-K 和 Top-P 保持默认就好。关于抽样能确定的是 Temperature=0 则输出概率最高的，其余情况按照**加权随机而非等概率**，但概率大的仍然更容易被抽中

## 六、大模型微调

**第一件事是前置判断**：微调是最后的手段不是第一选择，能用 Prompt + Few-shot 、RAG 等方式调整模型输出的，就别用微调。微调需要大量高质量数据集、需要 GPU 资源、需要工程经验（调参、防过拟合、防灾难性遗忘）、基础模型升级之前的微调版本基本就废了、训练数据更新

**第二件事是两个正交维度**：
- **改哪些参数**使用全量微调、LoRA（只改一小部分参数）、QLoRA 等微调技术
- **学什么目标**使用 SFT（监督微调）、DPO（直接偏好优化） 等微调技术
两个维度可以任意组合，LoRA 是方法、SFT 是目标，可以用 LoRA 做 SFT ，也可以用 LoRA 做 DPO

通常个人开发者使用 LoRA + SFT；有资源的使用 LoRA+SFT+DPO(社区主流)；大厂追求顶级用全量微调+RLHF（基于人类反馈的强化学习）

通常具备以下场景特征才会用到微调
- 模型需要持续以一种特殊风格输出
- 需要模型稳定掌握某类任务模式或内部术语
- 想用小模型替代大模型省成本
## 七、CoT 为什么可以增强推理能力

**CoT 能增强推理能力的原因**
模型是一个 token 一个 token 生成的，让它先组织推理步骤，等于给了它一张「草稿纸」，后面生成答案时能利用前面的推理上下文，自然出错就少了

**CoT 存在两种形式**
- **Few-shot CoT**：在 prompt 中给出几个完整的「推理示例」，效果稳定但 Prompt 长
- **Zero-shot CoT**：在 prompt 中添加一句「让我们一步步思考」，简单但效果稍差一点

**CoT 的局限性**
- Token 消耗更大、延迟也会增加
- 对简单问题适得其反，对纯记忆类任务没有帮助
- 推理链路本身也可能出错，一旦走错就全错

**CoT 的增强方式：Self-Consistency**
**首先**，调高 temperature，例如 0.7
**然后**，使用同一个 prompt 调用多次大模型
**最后**，程序收集多次调用中，出现概率最高的一条答案作为最终的答案回复给用户

## 八、模型为什么会出现幻觉及缓解方案
#### 8.1 模型幻觉的三个根本原因
- **第一是，训练数据层面**：互联网语料本身存在错误、矛盾、过时信息。模型把这些都「学进去」作为事实记忆
- **第二是，生成机制层面**：LLM 本质是「按概率续写下一个 Token」，不是「查知识库」。模型对「自己知不知道某件事」没有明显信号，碰到不熟悉的问题，会按训练时见过的相似上下文「编一个看起来合理的答案」。这就是 temperature=0 也会出现幻觉问题，概率最高的那条路径可能本身就是错的
- **第三是，对齐目标层面**：SFT（监督微调）和 RLHF（基于人类反馈的强化学习）时，「自信的回答」往往比「我不知道」得分更高，模型被无形中训练成了「不会拒答」
#### 8.2 三类幻觉分类
- **事实性幻觉**：编造不存在的事实
- **推理性幻觉**：推理链条错乱，前后矛盾
- **上下文不一致**：违背用户给的明确条件

#### 8.3 缓解幻觉三层组合
- **训练层**：对齐数据里专门加入「不知道就说不知道」的样例，做校准训练，让模型学会拒答
- **推理层**：让模型先做必要的分步分析再答、Temperature 调低减少随机偏差、Self-Consistency 多次采样投票
- **系统层**：RAG 接入外部知识库、强制模型携带引用源、对生成的答案进行二次核查

**最后**：幻觉不能完全消除，这是 LLM 概率生成机制的固定副产物。工程上目标是「降低发生率+让用户能识别」，不是「彻底消灭」

## 九、大模型部署有哪些主流方案

我理解大模型部署框架的本质问题是：怎么在固定的硬件上跑的更快、更省显存、支持更多并发用户
主流框架按定位分**四类**：
#### 9.1 vLLM 常见的部署框架
在当前生产部署里很常见的框架，核心创新是 PagedAttention，把 KV Cache 像操作系统虚拟内存一样分页管理，大幅减少碎片，显存利用率能明显提高。

#### 9.2 SGLang 是 vLLM 之后的新一代推理框架
核心创新是 RadixAttention，把多请求的共享前缀组织成树结构，相同前缀只存一份 KV Cache。在 Agent、多轮对话、批量 Prompt 场景下比 vLLM 显存更省、首 Token 延迟更低

#### 9.3 TGI（Text Generation Inference）
由 HuggingFace 出品，与整个 HuggingFace 生态深度集成。优点是开箱即用、支持各种 HF Hub 上的模型、企业级 API 接口

#### 9.4 llama.cpp 
**CPU / 边缘设备**部署的事实标准。用 C++ 重写整个推理栈，配合 GGUF 量化文件格式，可以让 7 B 模型在 MacBook Pro 上跑、在树莓派上跑、在手机上跑。是个人开发者和边缘部署的首选
