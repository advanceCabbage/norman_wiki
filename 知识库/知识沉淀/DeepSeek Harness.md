## 一、概要介绍
DeepSeek Harness 是一个基于 Web 端 AI Agent 平台，支持四种模式、支持自定义模型、支持查看整个 Agent 运转流程中的系统提示词、工具调用、模型和工具执行耗时、输入输出 Token 、缓存命中等

## 二、四种模式介绍

#### 2.1 标准模式
内置系列标准工具，包括文件编辑、Shell、网页搜索等。Agent 每轮根据当前结果决定下一步骤

#### 2.2 PTC 模式
保留标准模式的工具，PTC 模式允许模型写一段程序，将工具调用执行串连起来。这样多个工具执行的中间过程无需全部进入到模型上下文，模型交互次数也会减少

#### 2.3 极简模式
仅提供一句系统提示词，工具列表中也只有 Bash 和 str_replace_editor

#### 2.4 创造模式
普通模式让 Agent 使用现成工具干活。创造模式还能查看 Harness 里有哪些插件，把插件重新组合起来，创建一种新的工作模式。总结来说创造模式是组装新的 Agent 配置

## 三、适用场景与优势

#### 3.1 优势
- **全栈插件化、可塑性高**：支持新增工具、替换模型、Agent 循环、存储等
- **完整轨迹、可追溯流程**：会记录提示词、上下文注入、工具调用、结果、Token、耗时等，同时也支持恢复、分叉和回放。对排查故障、成本优化都很有价值
- **Creator、模式创新、可复用**：创造模式允许把插件重新组合成新的工作模式。企业可以把经过验证的提示词、工具权限和模型策略固化为可复用的 Agent 配置。和沉淀 Skill 有区别，Skill 是软约束，主要沉淀方法论和业务流程；创造模式是更底层的硬约束，定义 Agent 实际拥有哪些工具、权限、模型和审计能力。企业可以用创造模式先把 Agent 固化成受管岗位，再通过 Skill 持续沉淀该岗位的知识和 SOP
#### 3.2 劣势
- **稳定性差**：DeepSeek Harness 当前仍是开发者预览版本，存在 API 或插件兼容性变化的可能
- **企业套件成熟度、运维投入**：例如 SSO、多租户、合规认证等能力需要进一步验证或自行建设

#### 3.3 使用场景
我认为 DeepSeek Harness 的价值不在于替代 Codex 或 LangChain，而在于补齐企业 Agent 的运行时层。Codex 更适合作为成熟的研发 Agent 产品，LangChain 更适合作为业务 Agent 开发框架；DeepSeek Harness 则适合需要模型自主、工具自主、完整轨迹和可组合运行时的企业 Agent 平台。但它仍处于开发者预览阶段，因此应该从隔离、只读、可评测的场景开始试点
