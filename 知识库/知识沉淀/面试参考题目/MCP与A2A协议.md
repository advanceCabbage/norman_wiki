## 一、MCP 协议
**概念**：MCP 全称 **Model Context Protocol，模型上下文协议**，解决 AI 应用如何统一接入外部能力的问题

MCP 由三部分架构组成：
- **Host(宿主应用)** ：承载 AI 交互，管理 Client，协调模型、上下文和权限。例如Codex 就是 host
- **Client(客户端)**：Host 内部的协议组件，负责与某个 MCP Server 通信
- **Server(服务端)**：将外部系统的能力按 MCP 规范暴露出来。例如 业务 API 服务

Server 最核心的三类能力是：
- **Tools(工具)**：可执行的操作，带有名称、描述、参数 Schema 等信息
- **Resources(资源)**：可读取、供应用组织进上下文的数据。例如：文件内容、数据库表结构
- **Prompts(提示模板)**：可复用的交互模板。例如：一套标准的订单分析提示模板

协议层面，MCP 使用 **JSON-RPC 2.0** 表达请求、响应和通知；常见传输方式是本地的 **stdio** 和远程的 **Streamable HTTP**

## 二、A2A 协议
**概念**：A 2 A 全称 **Agent 2 Agent Protocol，智能体间通信协议**，解决独立 Agent 如何互相协作的问题

#### 2.1 第一，定义数据模型
A2A 的核心数据模型由五个部分组成，他们分别是：
- **Agent Card**：用于发现和接入 Agent， 包含 Agent 的身份、能力、调用方式等描述信息
- **Task 和 Artifact**：用于跟踪工作和交付结果，Task 通常会创建任务 ID 用于跟踪任务状态
- **Message 和 Part**：用于交流内容

####  2.2 第二，定义操作接口
A2A 的接口主要覆盖四件事。
- 第一是发送消息，通过 SendMessage 发起交互，需要实时反馈时使用 SendStreamingMessage
- 第二是管理任务，包括查询、列举和请求取消
- 第三是获取任务更新，可以订阅已有任务，也可以配置 Webhook
- 第四是获取能力信息，认证后可以读取扩展 Agent Card

#### 2.3 第三，定义底层传输
A2A 的第三层是传输绑定层，负责把上层的统一操作映射为具体网络调用。标准提供 JSON-RPC、gRPC 和 HTTP+JSON 三种绑定，分别适配不同的技术栈。Agent 在 Agent Card 中声明支持的接口，客户端选择双方都支持的接口进行通信。不同绑定的调用形式可以不同，但操作语义必须一致
