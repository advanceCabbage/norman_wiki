## Project Introduction(项目介绍)
#### 智能客服流程介绍 
About the AI customer support agent: We build it using a workflow. First, the agent identifies the user's question and decides whether to search the code or the knowledge base.

For code search, We use a lower-cost model to check whether the user has provided the API name and platform. if either is missing, the agent asks for the missing information. Once it has both, it searches the code using the Claude Agent SDK and returns the results.

For the knowledge base branch, we use hybrid search. We get 20 text chunks from vector search and 20 from keyword search. Then we combine the results, and use RRF to select the top 20 chunks. The AI customer support agent uses those chunks to answer the user's question. 

#### 智能客服用到的
We use BGE-M3 as our embedding model. We use Milvus  as our vector database.

#### 智能客服评测集
We use the evaluation dataset to make sure the agent's quality does not drop after each update. it includes several types of test cases:
1. **Missing knowledge**: Questions about how the agent works when this information is missing from the docs
2. **Incomplete user input** : The user only describes the problem, without providing the API name, platform, or environment.
3. **Retrieval quality**: Questions based on API documentation and real questions from past users. We check whether the right documents appear in the top 20 results and whether the agent answers correctly.
4. We also use other test cases to help ensure the agent's quality.

#### 智能客服的核心要点

We focus on four things to keep the quality high.
First, we keep the knowledge base up to date. When a document changes, we update the knowledge base automatically.

Second, we ask the agent to say "I don't know" when it's unsure.

Third, we review user questions and the agent's answers to find problems and improve the system.

Finally, we test the agent with many test cases after each update to make sure its quality doesn't drop.

## openClaw test workflow Project (端到端测试工作流)

Our testing workflow covers the whole process. First, it generates test cases from the requirements document. Then, two agents review the test cases. After that, it runs the tests and generates a test report.
