## 一、四层记忆机制

- **感知记忆**：当前输入的原始内容
- **短期记忆**：context window 里的对话历史，包括存入到 JSONL 中的文件
- **长期记忆**：存在外部数据库、语义检索召回
- **实体记忆**：已经历史对话提取的关键事实
实际设计时要解决三个核心问题：存什么、怎么存、什么时候取出来用

## 二、长期记忆的三种类型
- **情节记忆**：存的是具体的事件经历。比如：做了某件事，遇到什么问题，最终用什么方式解决
- **语义记忆**：存的是从多次经历中提炼出来的通用知识和规律。比如：多次遇到相似问题，跨多次经验总结出来的抽象知识
- **程序记忆**：存的是怎么做某件事的操作流程
三种子类型各有侧重，实际项目中通常会混合使用，**情节记忆提供具体的参考案例，语义记忆提供抽象的知识规律，程序记忆提供可复原的操作流程，三者配合起来才能让 Agent 的长期记忆真正好用。**

## 三、实体记忆介绍
存储对话中的关键实体和事实，存成结构化字段，通常使用精确查询。比如：用户偏好习惯、项目截止日期等。

## 四、记忆存什么？
通常值得存储的记忆分为三类：
- **用户偏好和习惯**，例如：语言风格、技术栈偏好等
- **任务执行中产生的关键结论和决策**，例如：调研发现的竞品的定价策略等
- **外部知识**：例如：产品文档、FAQ

## 五、怎么存记忆文件
- **向量数据库**：适合语义检索的存向量数据库，例如：文档知识、外部知识、任务执行中产生的关键结论和决策
- **结构化存储**：用户偏好和习惯

## 六、什么时候取记忆文件
- **主动检索**：每次任务开始前，用当前任务的描述去检索相关记忆
- **被动触发**：在 Agent 推理过程中，判断当前步骤需要某类特定知识时，主动发起检索。通过将「查记忆」封装成一个 Tool
实践中将两种方式搭配使用

## 七、社区开源的记忆存储库

#### 7.1 Mem0
核心思路是把记忆管理做成一个独立的服务层。用户只需要调用 memory.add()和 memory.search()做到存记忆和查记忆。底层的 embedding、去重等都由框架实现了。Mem0 特别适合「个性化记忆」场景，支持按照 user_id 做记忆隔离。而且它同时支持向量存储和图存储，在需要关系推理的场景也能用

默认使用的 Qdrant 向量数据库，没有引入图数据库（Neo4j 等），使用普通数据库维护**实体 ->  关系 -> 实体**

#### 7.2 Letta 莱塔
Letta 前身是大名鼎鼎的 MemGPT，Letta 把 Agent 的记忆分成了三个层级。
- **Core Memory** 是始终留在 context window 的核心信息，例如：用户画像
- **Recall Memory** 是最近的对话历史，类似于缓存，按时间顺序存储，支持快速回溯
- **Archival Memory**:长期归档的知识
最有意思的是，Letta 让 Agent 自己通过工具调用来管理记忆，Agent 决定在三个层级中移动记忆，例如将某条记忆从 Core Memory -> Recall Memory

#### 7.3 Zep
Zep 引入来「时间感知」的概念，Zep 给每条记忆标注「有效时间窗口」。通过时序知识图谱来管理记忆的生命周期，自动识别过期记忆。

## 八、生产级记忆整合策略

**目的**：消除内容重复、内容过期、互相矛盾的记忆内容，提升检索的质量

- **第一步去重**
把语义相近的多条记忆合并成一条更完整的版本

- **第二步冲突消解**
当两条记忆互相矛盾时，保留时间更新最近的那条，另外一条标记为过期

- **第三步抽象提炼**
本质上是把情节记忆转化为语义记忆的过程
