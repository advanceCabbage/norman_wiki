
## 一、总览

- **摘要压缩**是把长对话总结成简短摘要
- **滑动窗口**是只保留最近 N 轮对话
- **重要性过滤**是打分筛选，只留重要内容
- **结构化抽取**是把关键信息抽成结构化数据存起来

## 二、方案一：滑动窗口
**定义**：默认保留最新 N 条消息，超出就删除最老的消息

**优势**：实现简单、无 LLM 调用

**劣势**：历史信息中的关键决策也会被遗忘

## 三、方案二：摘要压缩

**定义**：调用 LLM 将历史对话总结成一段精华摘要，用摘要替换原始对话

**优势**：能记录关键决策

**劣势**：需调用 LLM、细节会丢失

**进阶版本**：**层级式摘要**，不是对所有历史做一次性摘要，而是分层处理，例如：保留最近 10 轮原文，10 到50 轮压缩成一份「中期摘要」，50 轮之前的历史进一步压缩成更精炼的「长期摘要」。**好处在于 Agent 既能精确回忆近期细节，也能粗略回忆远期要点**

## 四、方案三：重要性过滤

**定义**：调用 LLM 对历史对话进行打分，LLM 逐条判断每条记录的重要程度。通常在批量清理历史时做，而不是实时处理每条消息

**优势**：按照重要程度而非时间先后顺序评估价值，使得历史久远价值高的内容得以完整保留

**劣势**：每条记录都要调用一次 LLM，开销大

打分实现方式：
**方式一，规则打分**：包含「决定」「确认」等关键词的记录加分，被后续对话引用次数多的加分
**方式二，LLM 打分**：逐条判断每条记录的重要程度

## 五、方案四：结构化抽取

**定义**：很多场景里，真正有价值的不是对话文字，而是对话中传递的事实和状态。比如「用户偏好用 python」等。将这些信息主动提取出来，存成结构化字段，后续注入 prompt 时直接用提出的实体，信息密度也高很多。通常这类用户特征、实体使用关键字检索
