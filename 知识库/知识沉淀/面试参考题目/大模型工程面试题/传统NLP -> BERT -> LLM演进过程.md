## 一、传统 NLP
**NLP -> Natural Language Processing** （自然语言处理）

**工作方式**
传统 NLP 的工作方式是「流水线」式的，一个完整的任务需要被拆分为几个独立步骤，每一步用一个专门的模型来完成。原因是当时小模型能力有限，每个子问题必须单独训练模型才能完成

举个例子：做智能客服第一步就是分词，分词模型依赖于大量人工标注语料，假设遇到训练中没见过的新词，分词模型就无法工作了。这就是著名的 OOV（Out-of-Vocabulary，未登记词）问题


**NLP 存在的问题**
- 每一步都需要有自己的模型、自己的训练数据、自己的标注规范。整个过程冗长且脆弱，前一步失败后续都会失败
- 另一个点是迁移成本，换个领域（比如从客服换成医疗问答），所有模型基本都得重新训练

## 二、BERT
**BERT -> Bidirectional Encoder Representations from Transformers**（基于 Transformer 的双向编码器表示）

2018 年谷歌推出 BERT，整个领域出现了大转折。BERT 的核心创新是**预训练+微调**两阶段范式

**预训练阶段** 通过预训练 BERT 学会了“看懂文字”能力，通过两件事做到的
- 第一是**MLM（Masked Language Model，掩码语言模型）**，随机遮掉句子里 15% 的词，让模型根据上下文猜被遮的词是什么
- 第二是 **NSP（Next Sentence Prediction，下一句预测）**，给两个句子，让模型判断它们是不是连续的
两种方式都不需要人工标注，靠原始文本就能训练，所以可以用海量数据

**微调阶段**通过微调 BERT 可以将输出的每个 Token 的向量表示为具体内容。例如：要做问答，得接一个抽取式 QA 头

**BERT 存在的问题**
- BERT 不擅长生成文本，它的预训练目标是 MLM（填空题），每次只猜测一个被遮的词
- BERT 的输出是「向量表示」不是「文本」。每一种任务都需要单独设计标注数据、微调等

## 三、LLM
**LLM -> Large Language Model**（大语言模型）

LLM 最根本的转变，是把所有 NLP 任务统一成了一件事，**预测下一个 Token**，模型能做到预测下一个 Token 靠「**自回归 + 因果掩码**」两个步骤实现。
- **CLM（Causal Language Modeling，因果语言模型）**，给一段文本，模型从左到右一个字一个字的往后猜，每一步都要预测下一个 Token 是什么
- **自回归（Autoregressive）**，下一步的预测依赖于上一步的输出

两个关键点决定模型能力，分别是**数据规模 + 模型参数**
- **数据规模**：BERT 时代训练数据是几十亿词，而GPT-3 用了 3000 亿 token。原因在于因果语言模型无需人工标注，互联网上所有文本天然都是合格的训练数据
- **参数规模**：BERT 时代参数量是0.3B，而 GPT-3 是 175B，Kimi K3 是 2800B。
数据规模 + 参数规模的堆叠使得 LLM 走向新高境界

另外两个重要点也是 LLM 走强的原因，分别是 **In-Context Learning上下文学习**和**涌现能力Emergent Abilities**
- **上下文学习**：在 Prompt 中给模型几个例子，模型便能学会新的任务模型，不需要更新参数。例如下面的例子，模型能自动给出“橘子 -> orange”
```
苹果 -> apple
香蕉 -> banana
草莓 -> strawberry
橘子 ->
```
- **涌现能力**：在小模型上几乎看不到的能力，在数据规模和参数规模到达某个临界点突然表现出来的能力。例如：多步算术、上下文学习、跨语言迁移

**为什么会涌现？**
业界给出的工程经验叫 **Scaling Law**（缩放定律）。即模型规模、训练数据量、训练算力这三者之间存在一种可预测的关系：三个量按一定比例同时放大，模型的损失值会沿着一条幂律曲线下降

但要注意的是，涌现不是「越大越好」。最近几年的研究发现，超过某个规模之后，单纯堆参数的边际收益在递减。所以现在的趋势是，**参数堆得不一定要最大，但数据要够多、算力要够花**

## 四、这场转变对工程团队意味着什么

BERT判别式是输入文本输出标签，理解和生成是分开的；
LLM 是输入文本输出更多文本，理解和生成在同一个模型里完成。这是范式上的根本变化。

现在做 NLP 项目，工作方式从「先拆任务再选模型」变成了「先想 Prompt 怎么写」。**现在 LLM 工程师的核心技能是 Prompt Engineering、RAG 系统设计、Agent 编排、对齐微调**
