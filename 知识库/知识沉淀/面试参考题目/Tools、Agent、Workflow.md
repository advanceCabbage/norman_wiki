## 一、Tools 
**概念**：Tools 是整个体系中最底层的概念，它本质上是一个「按特定格式暴露给 LLM 的函数」，Tool 是给 LLM 调用的，因此 Tool 必须拥有一些大模型能看懂的 Schema，包括：名字、描述、参数类型

**写好 Tools 的三个原则**：
- 首先是「职责单一」，一个工具只做一件事
- 其次是「描述要精确」，模型完全靠你写的 description 来理解这个工具能做什么
- 第三是「错误信息要清晰」，工具执行失败的时候，返回给 LLM 的错误信息必须是它能「看懂」的
## 二、Agent
**概念**：Agent（智能体）是一个「围绕目标，自主决定并执行下一步行动的系统」。在大模型应用中，它通常以 LLM 为决策核心，根据任务要求和当前上下文，选择调用工具、向用户询问或委派其他 Agent，并根据执行反馈调整后续行动，直到完成任务、遇到阻碍或达到停止条件。Agent 通常包含：模型、任务指令、上下文与状态管理，以及“决策—执行—反馈”的运行循环，并按需接入 Tools 等外部能力

**使得Agent 停止运行的四大方式**：
- 第一种是 LLM 主动判断任务完成，这是最理想的情况
- 第二种是设置最大循环次数，比如最多跑 15 轮，超过了不管任务有没有完成都强制停下来，返回当前已有的结果并告知用户
- 第三种是设置总 token 预算上限，一旦消耗的 token 接近预算就停止，防止成本失控
- 第四种是超时机制，例如整个 Agent 运行时间超过比如 60 秒就终止

## 三、Workflow
**概念**：Workflow（工作流）是一个「按照预先定义的步骤和执行规则，组织并完成任务的流程」。它将任务拆成多个节点，规定每个节点做什么、需要什么输入，以及执行后进入哪个节点。节点可以是函数、Tool、LLM 调用或 Agent，并通过顺序、条件分支、循环、并行等方式组合。Workflow 通常包含：输入、处理节点、节点之间的依赖与控制规则，以及输出

## 四、Agentic Workflow 才是生产主流
目前生产环境里最主流的模式是**Agentic Workflow：用 Workflow 固定主流程的骨架，在需要灵活判断的节点嵌入 Agent，其余固定节点直接用 LLM 或 Tools**
