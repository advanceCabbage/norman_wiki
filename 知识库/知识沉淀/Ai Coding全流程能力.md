整个流程封装为 plugin

**首先**确认现有项目中 CLAUDE.md、AGENT.md 是否存在，假设不存在先由 claude code 的/init 初始化一份 CLAUDE.md。高频动作做成 Skill，主要记录：项目目录、启动命令、测试命令以及人工添加的防踩坑指南

**然后进入需求分析阶段**，我最近使用的是/grilling skill（其他例如 superpower、specKit 等），使用拷问式提问完善需求细节，产出 SPEC.md 文件，包括：需求修改范围、验收标准、端到端验证方式等。人工确认需求需求完整性、正确性，然后开新会话执行，避免把讨论垃圾带近实现上下文

**其次进入方案阶段**，复杂需求一律 Plan 模式，先只读探查再出方案，方案我会查看和完善，确认后才允许动代码。小改动无需制定 Plan

**代码实现阶段**由 agent 按照 Plan 方案进行实施

**验证阶段**，核心原则是“给 Agent 一个自己能跑的检查”，轻的写进 prompt，重的挂 Stop hook；在我们的场景，是基于 openclaw 分别定义两个 agent，一个 agent 用于生成测试用例，一个审核测试用例的完整性，对抗性审核。基于测试用例与代码的一致性也进行审核，最后通过真机执行测试用例，产生测试用例报告

**POC/迭代**，POC（Proof of Concept 概念验证）。先实现并验证核心原型框架，核心原型验证完成后，再反哺 Spec.md 文件

**规模化与风险**，多任务用 worktree 并行，不给 agent 提交代码或合并代码的权限，由人工确认 diff
