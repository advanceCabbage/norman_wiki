**配置 - 集成**
- 智能快照：同时按下两个 command 键，将当前屏幕截图自动放入最近的聊天窗口中
- 电脑操控：管理 Codex 如何使用你电脑上的其他应用程序
	- 任何应用均可使用 --- 开启
	- 允许锁屏操作 --- 允许ChatGPT 在 Mac 锁定时使用此 Mac

**配置-编码**
- 钩子：Hooks 是 Codex 的扩展框架。它们允许你将自己的脚本注入到智能代理循环中，在某个项目中配置的 Hooks 均会显示在这里
- 连接：添加远程设备（手机）连接并控制这台 Mac。选择使用 iPhone 的**密码**软件作为验证器接收验证码即可，隔几分钟会刷新一个。对于 codex 给出的待扫描二维码，使用 iPhone 的扫码功能扫描即可
- git ：支持拉取请求、推送请求、代码评审（当前对话中启动 /review，或发起单独的审查对话）
- 环境：支持为项目创建工作树、清理工作树时设置自定义执行脚本
- 工作树：设置工作树目录、自动删除工作树数量限制（LRU 算法）

## 二、Codex 实际使用技巧
#### 2.1 /plan 和 /goal （先计划再工作模式）
- **首先**使用**计划模型**与 codex 聊清楚需求
- **其次**使用计划模式时搭配 grilling skill [[superpower和Grill with doc的区别]] 并且为项目写好 AGENT.md
- **最后**启动**目标即/goal**，goal 的运行逻辑是你给它一个目标它就自己跑下去，不会停下来问你，可以连着跑几个小时甚至几天
#### 2.2 Side Chat
在/goal 跑的时候，你可能想了解它目前的进度，但又不想打断主任务。Side Chat 就是在主线程旁边开一个侧边对话，**从当前主对话临时 fork 出一个 side chat**。它有独立 transcript，主对话仍在，可在结束后回到主对话。在 side chat 中提问的内容无法自动合并回主对话，有需求可以手动复制给主对话。

#### 2.3 Codex 默认开启的两个开关
- Retained Reasoning ：保留推理过程
- 上下文压缩：从滑动窗口模式修改为摘要压缩
这两项在 codex 中默认是开启的，也是 Codex 在长任务上表现比调用 API 更好的原因。山姆奥特曼说他们开启了这两项模型得分提高了三倍

#### 2.7 Side Panel + 浏览器 + Computer Use
- Side Panel 打开的是内置 Browser：直接和浏览器标签页交互，主要通过 DOM、页面状态和浏览器自动化能力理解页面；适合本地前端预览与测试。具体而言，我连接到 “Codex In-app Browser”，接管了已打开的本地标签页，并读取了页面的 DOM 快照/可访问性结构
- Computer Use：通过视觉界面模拟操作 macOS 应用或浏览器，类似“看屏幕、移动鼠标、敲键盘”；适合没有可用网页自动化接口的桌面软件。
#### 2.8 长任务执行时定期保存结果
- Codex 每跑一段时间就做两件事：git commit 当前的修改，写一句进度摘要到 `progress.md`。如果崩了，开新 Thread，让它读 `progress.md` 和最后一次 commit，接着来
- 上下文太长的时候还有一个技巧：让 Codex 自己给自己写 handoff 文档。告诉它"把当前进度、已完成的部分、下一步计划写成一个交接文档，存到 handoff.md"。然后开新 Thread，第一句就是"读 handoff.md，接着做
- 官方的 Memory 可以当快速回忆层用。但真正靠得住的还是你文件系统里的那些 `.md` 文件。它们不会被压缩、不会被遗忘、不会因为换 Thread 丢失
- 长时间跑的 Goal，还有一个容易漏的东西：止损条件，例如：定义同一个错误重试三次则停止尝试，交给人工处理
